# 최종 설명 정밀성 개선 79

2026-09-10. 현재 로컬 후보는 **0.2.0-rc.10**이다.
목표는 원래 전문가 설명 과제의 H1–H3와 Q1–Q2를 실제 답변에서 모두 충족하는 것이다.
이번 실제 rc.9 Haiku 진단은 Q1에 실패했다. 후속 rc.10은 로컬 검증까지 완료했으며,
아직 모델의 수정 답변이 정밀성을 통과했다는 관측은 없다.

## 변경과 실제 결과

rc.9은 PostgreSQL 18 공식 문서와 SSI 구현 설명에서 확인한 범위·재시도·비용 근거를
번들 도구에 추가했다. 단일 읽기/쓰기 의존성을 무조건 abort 조건으로 설명하는 문장과
근거 없는 성능 크기 단정을 검사하고, Stop이 여러 문제의 피드백을 한 번에 전달하도록 했다.
입력은 실행하거나 외부로 전송하지 않으며 근거 URL도 런타임에 가져오지 않는다.
이 요약은 유한 시나리오 계산과 별개인 구현 근거로 표시한다.

이전 78의 실제 답변은 기존 검사에서 0건, 새 검사에서 3건이 검출됐다.
정상적인 조건부 설명·측정 결과·부정문·인용·다른 주제의 대조도 검사했다.
한 부정문을 잘못 지적하는 문제가 로컬 검사에서 발견돼 네이티브 실행 전에 수정됐다.

남은 진단 1회로 기존 전문가 과제를 실행했다. 모델은 `claude-haiku-4-5-20251001`,
Claude Code는 `2.1.266`, thinking 요청 상한은 8192로 유지했다.
정상 ON 정책, 정확한 skill 본문, 도구 결과 재계산 일치, 실제 Stop 실행,
프로세스 정리를 확인했다. 추가 과금용 API 키·fallback을 사용하지 않았다.

그러나 모델이 도구에 제출한 초안은 의사 예시에 한정됐고 완화책은 포함하지 않았다.
rc.9은 초안의 SERIALIZABLE 언급을 조건으로 근거를 제공했기 때문에 실제
`reference_notes`는 **0개**였다. 모델은 최종 답변에서 검토하지 않은 완화책 네 가지와
성능·사용 빈도·업계 관행에 관한 단정을 추가했다. Stop도 새 표현을 놓쳤다.

H1–H3 및 비용 설명 Q2는 유지했지만 Q1은 실패로 기록했다. 특히 물리적 직렬 실행과
직렬화 가능성을 혼동했고, 공통 count 행을 갱신하는 대안에서 기존 snapshot이 다른
트랜잭션의 commit을 곧바로 보게 된다고 설명했다. `costliest`나 `industry standard`
등의 비교·관행 단정에도 근거가 없었다. 검사 결과 0건을 품질 합격으로 간주하지 않았다.

## 후속 rc.10

- 초안에 완화책이 없더라도 두 구현 근거를 제공한다. 근거의 전달이 모델의 키워드
  선택에 좌우되지 않도록 했다.
- 도구 설명에 제안한 완화책과 비용까지 포함한 전체 답변 초안을 제출하도록 명시했다.
  이것만으로 모델이 항상 지킨다고 주장하지 않는다.
- 실제 최종 답변의 물리적 직렬 실행 단정과 비용 최상급 표현을 검사한다.
- 한 번의 Stop 교정, OFF 상태의 비개입, 입력·출력 상한을 유지한다.

79의 실제 입력·답변을 로컬에서 다시 처리한 결과, 근거는 0개에서 2개로 늘었고
최종 단정 3건이 검출돼 Stop 차단이 발생했다. 이는 실제 모델이 그 피드백으로
올바르게 수정했다는 증거가 아니다. 임의의 SQL 대안·업계 관행까지 검증하는 검사기도 아니다.

최종 검사: **Node 203개 통과, Python 77개 통과**. 정상 문장과 부정문 대조를 포함한다.
모델 호출 뒤 임시 ON 상태는 원래의 상태 파일 없음으로 복구했고, 후보 snapshot과
실패 판정은 `.superpowers/precision-79/`에 보존했다.

## 근거와 남은 검증

[PostgreSQL 18 격리 수준 문서](https://www.postgresql.org/docs/18/transaction-iso.html)는
직렬 실행과 동등한 결과, serialization failure 이후 전체 재시도, 추적·재실행 비용을 설명한다.
[PostgreSQL 18 SSI 구현 설명](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/storage/lmgr/README-SSI)은
위험한 의존성 구조와 순서 조건, 보수적 탐지에 따른 불필요한 abort 가능성을 설명한다.
특정 부하에서의 성능 크기나 모든 데이터베이스 구현으로 일반화할 근거는 아니다.

누적 **706회(Claude 420, Codex 286)**. 별도 추가 상한 6회는 모두 사용했다.
전체 비교 **516회는 미사용**이다. 전체 비교·Opus/Sol·출하는 시작하지 않았다.
남은 판별은 rc.10의 실제 전체 답변이 H1–H3/Q1–Q2를 충족하는지, 또는 Stop 피드백 뒤
그 상태로 수정되는지다. 로컬 재현 성공만으로 이 판별을 대체하지 않는다.
