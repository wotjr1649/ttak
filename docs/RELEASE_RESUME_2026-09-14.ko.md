## 사실 정확성 회귀: 207

증거 보존 수정은 `3f504db`에 커밋했다. 207의 Codex 전문가 설명은 동일 세션 활성화, 독립 검토자 2개, 영수증·정확한 최종 전달 및 종료 대조를 통과했지만, 의미 검토에서 불합격했다. 잠금 대기 후 같은 트랜잭션이 최신 상태를 재확인한다고 단정하면서 필요한 구현·격리 수준 조건을 명시하지 않았다. 잠금으로 실행 순서를 정하는 것과 읽는 버전이 바뀌는 것은 별개다.

[PostgreSQL 18 잠금 문서](https://www.postgresql.org/docs/18/explicit-locking.html)는 Repeatable Read/Serializable에서 잠글 행이 트랜잭션 시작 이후 변경된 경우 오류 경로를 구분한다. [격리 수준 문서](https://www.postgresql.org/docs/18/transaction-iso.html)는 직렬화 실패 시 트랜잭션 전체 재시도가 필요하다고 설명한다. 행 잠금 자체가 언제나 무효라는 주장이 아니라, 제시된 대기 이후 동작 설명의 조건 누락을 수정한다.

사실 검토와 최종 검토에 실행 순서·관측 버전·재시작 조건을 구분하는 지침을 공유했다. 기존 검토 항목 수나 반환 검증 상한은 늘리지 않았다. `tests/fixtures/visibility-regression.json`에 실제 실패와 공식 출처에 근거한 회귀 과제를 보존했다. 이는 실제 데이터베이스 실행 시험이나 모든 미래 답변의 정확성 보증은 아니다. 207은 native 시작 2회, 응답 11개, 관측 221,649토큰이며 누적 시작은 1,188회(Claude 690, Codex 498)다. 이후 원래 비교 행은 실행하지 않았다.

수정 후 Node 916개, Python 101개, conformance, 요구 ID 157개 일치 및 diff 공백 검사가 통과했다. 건너뛴 로컬 검사는 없다. 증거는 `.superpowers/checkpoint-208/`에 보존했다. 새 지침의 실제 모델 회귀는 아직 실행하지 않았으므로 결함 해결 완료로 단정하지 않는다.
