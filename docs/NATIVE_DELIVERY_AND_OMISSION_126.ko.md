# Native 보류 전달 교정과 요청 평가 누락 — 126

후보 `0.2.0-rc.13+codex.20260912162505`에서 단계별 Stop 교정이 실제로 작동했다.
Haiku는 처음 보류문을 다시 쓰고 요구 변경안을 덧붙였으나, 정상 Stop의 전달 전용
교정 뒤에는 이미 발급된 본문을 정확히 전달했다. Stop은 정상 종료했고 원문 해시와
withheld 상태가 유지됐다. 단, 요청된 T1 읽기 오류 평가는 모든 본문에서 누락되어
배치 전체는 FAIL이다. 근거는 `.superpowers/release-loop-126/`에 보존했다.

## 변경과 근거

- 결정 전 검증 안내와 결정 후 본문 전달 교정을 별도 분기로 나눴다. Codex의 교정용
  새 prompt에서도 초기 절차를 재주입하지 않는다. 실제 Haiku 전달 교정 PASS,
  Codex 새 교정 분기는 로컬 PASS / 이번 native UNRUN이다.
- 원래 본문 해시, 독립 완료 근거, 실패 보존, 단 한 번의 Stop 교정 예산은 유지했다.
- 보류·완료 안내 오류 2개를 수정 전 재현했다. 첫 수정 검사에서는 turn ID가 해시로
  저장되는 기존 계약을 새 테스트가 원문으로 가정한 오류를 바로잡았다. 이후 집중
  126 PASS, 전체 Node 45파일 / 531 PASS / 0 skip, Python 78 PASS, conformance PASS.
- 정상 Haiku 보류 20,066ms / 응답 3개 / 74,502 tokens, 내부 Agent 0개.
  상위 native 3/8, 관리 7/7(복원 2/2), 후속 5행 UNRUN. 두 프로필 선택과 task-created
  ON 파일 부재를 복원했고 캐시·실패 근거는 유지했다. 누적은 900회(Claude537 / Codex363).

## 다음 조사 계층

보류문을 올바르게 전달하더라도, 명시적인 별도 평가 요구를 생략하면 전체 요청을
처리한 것은 아니다. 122·126의 실제 누락은 선택적인 corrections 필드와 안내만으로
요구 보존을 확보하지 못함을 보여 준다. 127은 독립적인 보류문 검토를 추가한다.

원래 요청 전체와 제안된 보류문을 새 native 검증자에게 전달하고, 실제 native receipt와
정확한 본문 해시가 있어야 보류 전달을 승인한다. 이 승인은 완성 설명 complete와
별개다. 보류문 문제는 한 번 수정할 수 있으며, 실패/취소·원문 불일치·다른 native
신원·지출된 예산을 바꾸어 복구하지 않는다. 원래 요청과 본문은 기존 MCP의 유한
메모리에만 두고 durable state는 해시·수량·receipt만 기록한다. 기존 실패는 보존한다.

전체 목표는 active / No-Go다. 원래 H/Q 정상 과제·검사 실패·취소·새 사례·반복과
192 subjects / 516 requests 비교는 별도 미완료 출하 조건이다.
