1. root가 현재 작업 트리와 위 핵심 증거를 읽고 확인한 사실/미확인/새 가설을 구분한다. 사용자 기준, 네 기능, 최신 계수, 후보 버전과 비교 조건을 짧은 공통 검토 입력으로 만든다.
2. `$grilling`의 질문을 사용자 대신 독립 서브에이전트에게 맡긴다. 증거·판정 감사, 최소 새 개입 설계, 반론·실행비용 검토를 병렬로 수행한다. 각 역할에 필요한 검토된 최소 입력과 종료 조건만 제공하고 같은 파일을 함께 편집하지 않는다. 의견은 품질 trial이나 실행 권한이 아니다.
3. 1차 결과와 필요한 상호 반론 1회 후 root가 하나의 후보를 선택한다. 선택 근거는 기존 실패 원인에 작용하는 실제 변경 지점, 원래 범위 유지, 최소 반증검사, 설치 경로, 비용과 중단 조건이다. 새 컨텍스트나 문구 교체 자체를 새 근거로 삼지 않는다.
4. 선택된 후보가 있으면 허용된 범위에서 로컬 구현과 가장 작은 유효 검사를 완료한다. 로컬 통과, 실제 호스트 통합, 낮은 모델 품질, 전체 비교를 별도 단계로 기록한다. 네이티브 진단 전에는 아직 품질 해결을 선언하지 않는다.
5. 새 진단은 별도 고정 계획으로만 검토한다. 알려진 실패·정상 대조·조정에 쓰지 않은 과제를 어떤 비용으로 확인할지 먼저 계산한다. 잔여 2회만으로 네 기능 전체 출하를 입증할 수 없다. 첫 실패나 미확인 시 다음 실행을 중단하는 조건을 사전에 정한다.
6. 전체 비교 착수 조건을 실제 근거로 충족한 뒤 후보와 입력·버전·판정 기준을 새로 freeze하고 전체 검증을 진행한다. 준비물 `.superpowers/low-model-preparation-58`은 실행 완료도, 알려진 결함 해소도 아니다. 비교 도중 후보를 조정하면 같은 후보의 고정 비교가 아니다.

한 차례 분석이 끝났다는 이유로 영구 불가능 판정을 내리지 않는다. 동시에 조사만 늘리지 않는다. 후보가 없으면 어느 구체적 전제가 막혔는지, 그것을 판별할 한 가지 검사와 필요 자원, 재진입 조건을 남긴다. 사용자가 해야 할 일이 실제로 필요하면 실행 파일·명령·예상 결과·상한·중단 조건까지 준비하고 정확한 효과만 묻는다. publish/배포 대상과 권한은 아직 정해지지 않았다.

출하 완료는 실제 설치 후보의 모든 원래 기준을 관측 근거로 충족했을 때만 선언한다. 로컬 후보 완성이나 부분 진단 통과는 해당 범위의 성과다. 현재 세션의 인계 완료를 원래 출하 목표 완료로 표시하지 않는다.
