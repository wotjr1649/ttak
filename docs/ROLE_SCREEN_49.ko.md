# 역할 분리 후보의 첫 품질 시험 — 진단 49

2026-09-09. **첫 Claude 근거 검토에서 필수 오류 누락을 확인해 후보 시험을 중단했다.**
이번 추가 모델 호출은 1회다. 나머지 17개 작업은 실행하지 않았고, 출하 판정은 미통과다.

## 실행과 판정

진단 47의 case-a 전체 16문단과 동일 과제, 검토한 출처 요약을 전달했다.
기대 오류 위치와 operator 판정 기준은 작업자에게 전달하지 않았다. 프롬프트,
출력 규격, 런타임 파일, 입력, 판정 기준, baseline 프로필 준비 메타데이터와 실행 파일
해시를 `.superpowers/role-screen-49a/execution-manifest.json`에 고정했다.
실행 후에도 고정 파일의 일치를 확인했다.

| 항목 | 관측 결과 |
|---|---|
| 실제 CLI / 모델 / effort | Claude 2.1.266 / claude-sonnet-5 / medium |
| 정확한 프롬프트·세션·출력 검증 | 통과 |
| 반환된 문단 / 주장 | 16문단 / 14개 주장 |
| 판정 분포 | supported 7, contradicted 3, not_established 4 |
| 미리 지정한 필수 오류 | U007·U013 발견, U014 누락: 3개 중 2개 |
| 별도로 발견한 오류 | U007의 snapshot 생성 시점 설명 |
| 감독된 네이티브 실행 시간 | 83.795초 |
| 종료 후 Job Object 활성 프로세스 | 0개 |

시간은 이 한 번의 관측값이다. 로컬 회귀 테스트 실행이 일부 겹쳤으며, 전체 비교의
지연 예측이나 성능 비교 수치로 사용하지 않는다.

U014의 반환 기록에는 잠금 요청이 상대 transaction의 종료를 기다린다는 앞부분만
`supported`로 들어 있다. 뒤에 이어지는 **대기 후 최신 상태를 보고 진행한다는 문장**은
어느 판정에도 포함되지 않았다. 이는 그 문장을 옳다고 명시 판정한 사례와 구별되는
**주장 추출·검토 누락**이다. 문단 ID를 모두 반환한 것으로 이 누락을 해소할 수 없다.

PostgreSQL REPEATABLE READ에서 snapshot 이후 대상 행을 변경한 transaction이
commit하면, 대기 중이던 transaction은 snapshot을 갱신해 계속하는 대신 serialization
failure를 처리하고 전체 transaction을 재시도해야 한다. 앞선 집계 쿼리는 별도로 잘못된
SQL이므로, 여기서는 유효한 행 잠금으로 바꾸더라도 뒤의 설명이 성립하지 않는다는 점을
판정했다. [PostgreSQL 18 transaction isolation](https://www.postgresql.org/docs/18/transaction-iso.html)
및 [SELECT locking clause](https://www.postgresql.org/docs/18/sql-select.html).

이 구분은 작업자에게 제공한 PG18-ISO 요약에도 이미 포함돼 있었다. 출처 검색 실패나
본문 전달 실패로 설명할 근거는 없다. 다만 한 번의 관측으로 내부 추론 원인을 확정하지
않는다. 나머지 14개 주장과 이유는 root agent가 모두 검토했다. `not_established` 4개는
그대로 보존했으며, 미확인이라는 이유만으로 사실 오류로 재분류하지 않았다.

고정된 필수 오류를 첫 근거 검토가 누락했으므로 다음 호출 전에 중단했다. 문맥 검토가
이 누락을 보완할지는 시험하지 않았다. 따라서 이 결과는 **현재 후보의 첫 단계가
정해진 기준을 통과하지 못했다는 증거**이며, 두 역할의 모든 조합이 불가능하다는
결론이나 Codex의 실패 결과가 아니다.

## 장부와 보존

새 `scripts/review-screen-ledger.cjs`는 양 호스트가 공유하는 순차 호출 장부다.
작업 디렉토리를 독점 생성해 먼저 예약하고, 실제 결과의 SHA-256에 묶인 operator
판정이 기록되어야 다음 작업이 열린다. 미판정·실패·중단된 작업은 재호출할 수 없고,
중단된 프로세스의 예약도 다시 열어 중복 실행하지 않는다. operator 판정은 평가 기록이며
사용자 권한을 생성하는 장치가 아니다.

`.superpowers/role-screen49.cjs`는 호출을 한 번씩 실행한다. 수정·재검토 단계의 입력은
이전 검증 결과와 기존 제한 수정 모듈로만 구성한다. 이번에는 그 단계에 도달하지 않았다.
장부 상태는 `stopped`, 사용량은 1이며 다음 모델 호출은 열리지 않는다.

초기 준비에서 단계 이름의 underscore가 장부의 ID 규칙과 맞지 않아 실패했다.
`.superpowers/role-screen-49/`에는 그 실패 기록을 보존했다. 검증 규칙을 완화하지 않고
허용된 hyphen ID를 쓰는 새 `role-screen-49a` 준비본을 만들었다. 이 준비 실패와
복구에는 모델 호출이 없었다.

주요 기록:

* `.superpowers/role-screen-49a/execution-manifest.json`: 고정 입력과 실행 파일 해시.
* `.superpowers/role-screen-49a/ledger/case-a.claude.evidence-review/`: 예약, 실제 결과,
  결과 해시에 묶인 중단 판정.
* `.superpowers/role-screen-49a/native/`: 네이티브 출력, 실제 설정 감사, 프로세스 종료 기록.
* `.superpowers/role-screen-49a/screen-result.json`: 최종 판정과 호출 장부 요약.

새 장부 검사 6개와 기존 57개, **관련 Node 테스트 63개가 모두 통과**했다. 순서 위반,
중복 예약, 미판정 결과, 결과 변경, 음수 호출 계수, 중단 후 재개를 거부하는 검사를
포함한다. 이 로컬 통과를 모델의 사실 검증 능력과 혼동하지 않는다.
데이터베이스 실행과 Python 전체 회귀 검사는 수행하지 않았다.

## 사용량과 다음 판단

이번에 Claude 1회를 추가해 누적 기록은 **676회 = Claude 397 + Codex 279**다.
기존 진단 잔여량은 25회에서 **24회**가 됐다. 계획한 18회 중 1회를 사용하고 17회는
중단으로 미실행 상태다. 이를 새 후보의 자동 실행 예산으로 전환하지 않는다.
전체 비교 배정 516회와 출하 합격 기준은 유지한다.

호스트가 보고한 이번 usage는 input_tokens=4, cache_creation_input_tokens=22344,
cache_read_input_tokens=14027, output_tokens=10509다. CLI 1회와 내부 요청·캐시 토큰은
다른 계수다. 이 한 번의 시간·사용량으로 전체 비용이나 구독 잔여율을 환산하지 않는다.

현재 역할 분리 후보를 제품에 연결하거나 전체 비교를 시작할 근거는 부족하다.
동일 입력 재시도, 문구 보강만 한 재실험, 누락 문장을 작업자에게 알려 주는 방식으로
통과시키지 않는다. 다음 접근에는 **문단 처리와 별도로 실질적 주장 누락을 어떻게
확인할 것인지**에 대한 새로운 근거가 필요하다. 이를 마련하지 못하면 이 접근은
보류하고 남은 호출을 보존한다. 기존 제품 스킬·후크·문단별 실행부는 변경하지 않았다.
