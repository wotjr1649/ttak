# 제한 조건 적용 후 호스트 출력 계약 확인 71

상태: 고정 실행 파일의 정적 계약을 확인했다. 검토한 출력 제어 후보는 구현으로 넘기지 않는다.
품질 진단 호출 0회, 누적 진단 698회·잔여 2회·전체 비교 516회 미사용을 유지한다.

## 적용한 조건

새 후보는 실패 원인에 개입하는 실제 지점을 제시해야 한다. 우리 코드의 로컬 검사,
실제 호스트 동작, 낮은 모델의 품질 관측을 분리한다. 화면만 바꾸거나 정상 답변 대신
차단 메시지를 표시한 결과를 기존 네 기능의 성공으로 세지 않는다. 보편적인 결정론을
새 제품 요구로 추가하지도 않는다. 이번 작업은 이 조건에서 구체적 연결 지점이 있는지 확인했다.

## 확인 방법

설치된 Codex CLI의 해시가 진단 68에서 사용한 0.153.4 실행 파일과 같음을 확인했다.
로컬 `app-server generate-json-schema --help`를 읽은 뒤, 실행 파일 자체의 정적 스키마
내보내기를 수행했다. experimental 필드도 포함해 416개 파일, 4,137,012바이트를 얻었다.
20초 실행 제한과 5초 정리 제한을 적용했고 정상 종료·하위 프로세스 0개를 확인했다.

이 명령은 app-server 서비스 시작이 아니다. 별도 작업 디렉토리와 인증 정보 없는 환경에서
메타데이터만 내보냈으며 모델 요청·MCP 연결·계정 로그인·기존 프로필 변경은 하지 않았다.
메타데이터 내보내기 1회는 별도로 기록하며 Haiku/Luna 품질 trial로 계산하지 않는다.
Claude CLI의 로컬 도움말에서도 구조화 출력 및 입력/출력 모드를 확인했다.

원본 스키마와 파일 해시는 `.superpowers/host-contract-71/schema/`, `manifest.json`에,
판정 근거는 `findings.json`에 보존한다. 이 증거는 정적 계약이며 실제 화면·저장·재개 동작의
검증이 아니다. 새 hook을 활성화하거나 대화 내용을 주입·삭제하는 테스트는 하지 않았다.

## 후보별 판정

| 후보 | 고정 버전에서 확인한 내용 | 이 작업의 판단 |
|---|---|---|
| `thread/inject_items` | 새 user turn 없이 raw Responses items를 model-visible history에 append하는 app-server 요청 | 기존 최종 답변을 교체하거나 plugin의 정상 답변으로 표시한다는 계약이 아님. 즉시 채택하지 않음 |
| `TurnStartParams.outputSchema` | 해당 turn의 최종 assistant 메시지를 JSON Schema로 제한 | 구조 제한을 사실 정확성 검사로 해석하지 않음. 계산 이후의 동적 schema 전달을 기존 plugin이 소유한다는 증거도 없음 |
| hook 완료 출력 | warning, stop, feedback, context, error 종류를 정의 | 이 출력들을 정상 assistant 답변 대체 기능으로 취급하지 않음 |
| `thread/rollback` | 이력 끝에서 turn을 제거하는 deprecated 요청 | 오답을 이력에서 지워 품질을 통과시키는 해결책으로 사용하지 않음 |
| Claude `--json-schema` | print 모드의 구조화 결과 검증 옵션 | native plugin 최종 표시/재개 동작이나 문장의 사실성을 보장하는 기능으로 확대 해석하지 않음 |

Codex 요청 스키마는 app-server client와 host 사이의 계약이다. 요청이 존재한다는 사실만으로
설치 plugin이 현재 대화의 controller 권한이나 최종 표시 경로를 소유한다고 볼 수 없다.
별도 client를 만들면 인증·세션·사용 흐름이 달라질 수 있으므로 기존 plugin의 작은 수정으로
몰래 도입하지 않는다. 알려진 정적 API의 부재/제한이 모든 가능한 경험적 품질 개선의 불가능성을
증명하는 것도 아니다.

## 결과와 다음 조건

이번에 검토한 history injection, JSON output schema, hook 제어 출력은 현재 제약에서
자유 재작성 오류를 해결하는 검증된 제품 후보가 되지 못했다. 따라서 새 출력 엔진을 만들거나
남은 두 모델 호출을 사용하지 않는다. 진단 69의 stop과 원래 네 기능·고정 비교 기준을 유지한다.

재개 근거는 기존 기록을 다시 시험하는 것이 아니라, 다른 실제 개입 지점과 그 효과를
검증할 구체적 설계여야 한다. 지원된 정상 출력 경로, 의미 보존에 작용하는 방법, 미지원/실패 시
완결성 처리, 실제 호스트 검증 및 품질 관측 비용이 명시돼야 한다. 새 근거 없이 같은 API 목록을
다시 검색하거나 더 많은 렌더러·검토기 코드를 만드는 작업은 반복하지 않는다.

제품 코드·스킬·hook·기존 시험 장부에는 변경이 없다. 문서와 정적 계약 분석 산출물만 추가했다.
