# 제한된 네이티브 계산·설명 진단안

상태: 사용자가 진단 64를 1회 실행했고 사후 분석을 완료했다. 재실행 금지.

## 실행 결과와 정정

후속 오프라인 작업 65에서 JSON/텍스트 응답을 구분하는 공용 감사 모듈을 구현했다.
관련 25개 테스트와 저장된 실제 64 응답의 재검사를 통과했다. 모델 호출은 추가하지 않았다.

제품 방향은 원문 복사를 정확성 보증 수단으로 채택하지 않는 것이다. 진단 64의 복사
요구 실패는 그대로 보존한다. 후속 진단은 새로 사전 정의한 조건에서 모델이 구성한
시나리오의 충실성, 도구 결과 일치, 최종 설명의 정확성·범위·독자 적합성을 각각 평가해야
한다. `semantic_quality_verified: false`를 도구 일치나 원문 포함 여부로 자동 변경하지 않는다.
원래 16과제의 필수·품질 기준과 원본/기본 모델 비교 요구는 변경하지 않는다.

유한 불리언 계산은 일부 동시성 예제를 검토하는 수단이며 다른 독자별 설명과 네 기능
전체를 대체하지 않는다. 동일 예제 한 번의 성공만으로 제품 통합이나 Luna·전체 비교
실행을 시작하지 않는다. 다음 실행부에 수정된 감사를 연결하고 원래 과제와 다른 구조의
예제에서도 내용 검토가 가능하도록 준비한 뒤 별도 진단을 결정한다. 새 호출은 아직 없다.

세션 `5145d1c0-7074-4344-abfc-0669bcfd2e89`에서 실제 Haiku·프롬프트·thinking 및
도구 1회 호출을 확인했다. 19.3초 뒤 정상 종료했고 하위 프로세스 0개로 정리됐다.
모델이 작성한 입력은 두 의사 예제에 충실했고 도구 반환값은 재계산한 구조와 정확히 같다.

원래 감사의 `response_contains_expected: false`는 검사기 오류였다. Claude가 구조화된
반환값을 JSON 문자열로 기록했는데 감사는 JSON을 해석하지 않고 줄바꿈이 포함된 원문을
검색했다. 별도 오프라인 재검사로 전체 explanation과 facts의 일치를 확인했다. 잘못된 JSON,
변경된 설명, 변경된 facts를 거부하는 세 반례도 확인했다. 원본 감사와 실행 코드는 보존했다.

`final_contains_expected: false`는 실제 실패다. Haiku는 결과를 그대로 복사하지 않고 다시
설명했다. 따라서 사전 정의한 원문 보존 진단은 실패 상태를 유지한다. 다만 답변 자체를
수동 검토했을 때 원래 과제의 필수 3항목과 품질 2항목은 충족하며, 교차 읽기·쓰기와
조건 불충족을 올바르게 구분하고, 검증 범위를 과장하지 않았다. 단일 수동 검토 결과이며
설치 제품 검증·반복 관측·기본/원본 비교 합격은 아니다.

`.superpowers/scenario-native-64/operator-reassessment.json`에 원본 해시와 정정을 남겼다.
누적 695회(Claude 412, Codex 283), 진단 잔여 5회, 전체 비교 배정 516회 미사용이다.
아래 명령은 실행 당시 절차를 보존한 것이며 다시 실행할 지시가 아니다.

사용자가 직접 실행할 경로와 방법을 요청해 아래 실행 파일과 고정 프롬프트를 준비했다.
`prepare`와 `check`만 실행했으며 `already_started: false`를 확인했다. 모델 호출은 0회다.
새 실행 감사 테스트 3개와 기존 관련 검사 20개가 통과했다. 최종 감사 수정 후 새 3개도
다시 통과했다. 이 테스트의 합성 기록은 감사 코드 검증용이며 모델 품질 증거가 아니다.

## 사용자가 실행할 명령

일반 PowerShell에서 아래를 실행한다. 관리자 권한이나 별도 설치는 필요하지 않다.

```powershell
Set-Location -LiteralPath 'D:\AI_DEV\ttak\.superpowers\worktrees\first-release'
& 'C:\Program Files\nodejs\node.exe' '.superpowers/scenario-native64.cjs' check
```

`ready_without_model_call`과 `already_started: false`일 때만 다음 명령을 한 번 실행한다.

```powershell
& 'C:\Program Files\nodejs\node.exe' '.superpowers/scenario-native64.cjs' run
```

스크립트가 읽는 전체 프롬프트는
`docs/prompts/2026-09-10-session-01-haiku-finite-scenario.md`다. 파일을 직접 붙여넣지 않는다.
기존 과제와 설명 지침에 도구 사용·결과 보존 요청을 추가했으며 사례 정답은 넣지 않았다.
설정은 이번 자식 프로세스의 CLI 인수로만 전달한다. 소스·프롬프트·실행 파일 해시가
바뀌면 호출 전에 멈추며 출력 디렉토리를 배타적으로 생성해 중복 실행을 거부한다.

결과는 `.superpowers/scenario-native-64/`에 저장한다.

- `summary.json`: 호출 수·모델·세션 및 자동 검사 결과.
- `answer.md`: 모델의 최종 답변. 반환된 경우 저장한다.
- `audit.json`: 실제 모델·프롬프트, 도구 인수·응답과 최종 답변 보존 검사. 생각 본문은 저장하지 않는다.
- `process.json`: 프로세스 종료와 하위 프로세스 정리 결과.
- `failure.json`: 실행이나 감사가 중단됐을 때의 단계. 없을 수 있다.

`mechanical_checks_passed_manual_review_required`는 전달·형식 검사 통과다. 답변의 사실성,
시나리오 적합성, 원래 과제 충족 여부는 아직 판정하지 않았다. `checks_failed_do_not_retry`
또는 `stopped_do_not_retry`면 재실행하거나 출력 폴더를 삭제하지 말고 표시된 상태를 전달한다.
인증 실패, 버전 변경, 거부가 있더라도 설정을 우회하거나 다른 모델로 바꾸지 않는다.
실행이 끝나면 사용자는 이 대화에 완료 여부와 마지막 상태를 알려주면 된다. 같은 작업
폴더에서 답변·도구 기록을 다시 읽어 실제 설명 품질을 판정한다.

진단 63에서 올바른 계산 결과를 제공해도 Haiku의 최종 설명이 검증 범위를 과장했다.
다음 진단은 모델이 직접 유한 시나리오를 구성해 `scenario_explain`을 호출하고, 코드가
생성한 핵심 설명을 최종 답변에서 보존할 수 있는지 확인한다. 이것이 성공하더라도
한 전문가 과제의 단일 진단이며 범용 설명 품질이나 제품 합격으로 세지 않는다.

## 범위와 실행 제한

- 호스트: Claude Code 2.1.266, 기존 격리된 `claude-baseline` 구독 프로필.
- 모델: `claude-haiku-4-5-20251001`, thinking 요청 8192, effort 미지정.
- 최대 CLI 호출 1회, 재시도 0회, 120초와 정리 10초, stdout 1 MiB / stderr 64 KiB.
- 기존 Windows Job Object 실행기로 하위 프로세스까지 정리하고 active process 0을 확인한다.
- 서버는 프로세스별 stdio만 사용하며 도구 호출은 연결당 최대 3회다.
- 셸·파일·웹 등 기본 도구를 끄고 정확히 이 MCP 도구만 세션 한정으로 허용한다.
- 구독만 사용하며 API 키·추가 크레딧·fallback 모델은 사용하지 않는다.
- 진단 잔여 6회 중 1회만 사용한다. 실패하면 Luna나 같은 입력 재시험으로 이어가지 않는다.

## 연결 설정 초안

다음은 검토용 예시이며 현재 설정 파일이나 설치된 프로필에는 적용하지 않았다.
Claude의 로컬 `--help`에서 `--mcp-config`, `--strict-mcp-config`, `--tools`,
`--allowedTools` 지원을 확인했다. 실제 실행은 `--tools ""`, strict MCP와 아래 서버만
사용하고 `mcp__finite_scenario__scenario_explain`만 세션 한정으로 허용한다.

```json
{
  "mcpServers": {
    "finite_scenario": {
      "command": "C:\\Program Files\\nodejs\\node.exe",
      "args": ["D:\\AI_DEV\\ttak\\.superpowers\\worktrees\\first-release\\scripts\\finite-scenario-mcp.cjs"],
      "env": {"CLAUDE_CODE_OAUTH_TOKEN": "", "ANTHROPIC_API_KEY": "", "OPENAI_API_KEY": ""}
    }
  }
}
```

서버는 입력 JSON을 제한된 불리언 상태와 식별자로만 해석한다. 문자열 실행, 파일 접근,
네트워크, 모델 호출이 없고 오류 메시지에 입력을 반사하지 않는다. 네이티브 입력에는
검토된 공개 과제·현재 설명 지침만 넣는다. 서버에 인증 정보는 필요하지 않다.
전역 설정·설치·신뢰 목록은 바꾸지 않는다. 설정 초안은 검토 가능한 산출물이며,
실제 연결과 세션 한정 도구 허용은 Global Contract S3의 MCP/permission 효과다.

## 입력과 합격 증거

기존 `tests/release/cases.json`의 `explain-expert` 과제 및 현재 정책·설명 본문을 그대로
사용한다. 추가 지시는 시나리오를 도구 입력 형식으로 구성하고, 성공한 도구의 설명
본문을 변경 없이 최종 답변에 포함하며, 추가 설명이 계산 범위를 넘지 않도록 요청한다.
시나리오의 정답, 사람이 만든 입력 JSON, 예상 의존성·스케줄은 모델에 제공하지 않는다.

판정 전에 다음을 각각 확인한다.

1. 실제 모델·버전·정확한 입력·세션, 도구 이름·인수·응답·호출 순서와 종료 상태.
2. 모델이 만든 시나리오가 과제에 맞는 비자명한 예제인지: 입력 스키마 통과만으로 합격하지 않는다.
3. 반환 설명 본문이 최종 답변에 그대로 포함되는지와 범위 제한 유지 여부.
4. 추가 문장 및 전체 답변의 메커니즘·예제·해결책·대가가 원래 필수 품질을 충족하는지.

인증·도구 거부·추가 도구·잘못된 입력·설명 변조·중대한 사실 오류가 있으면 해당
실패를 보존하고 중단한다. 정상 메시지를 임의로 보충하거나 답변을 사람이 고쳐서
성공으로 세지 않는다. 실제 도구 호출 로그와 계산을 재대조하며 모델 자체 평가는 증거가 아니다.

성공 후에만 같은 가설의 Luna 실행 준비, 두 호스트 반복 검증, 설치 제품 통합 여부를
판단한다. 이 진단은 원본 대비 퇴보와 기본 모델 대비 반복 개선의 전체 비교를 대체하지 않는다.
Opus·Sol은 Haiku·Luna의 전체 합격 후 별도 검증 계획으로 유지한다.
