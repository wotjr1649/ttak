# 주입 지침과 설명 검토 크기 실측 — 2026-09-14

대상 runtime은 `ec0ee9f`의 `0.2.0-rc.13+codex.20260914091452`다. 제품 변경이나 새 모델 호출 없이 로컬 코드와 완료된 209 기록을 측정했다. 크기는 UTF-8 byte이며 토큰 수로 환산하지 않았다. 아래 KB는 1,000 byte다.

## 정적 지침과 도구 정의

| 항목 | UTF-8 byte | 적용 범위 |
|---|---:|---|
| 메인 공통 정책 | 3,645 | ON 상태의 메인 정책: precedence + invariants + contract |
| 하위 에이전트 공통 정책 | 2,303 | precedence + invariants; 메인 정책의 부분집합 |
| 진행·응답 contract 본문 | 1,340 | 메인 공통 정책에 이미 포함; 별도 가산하지 않음 |

스킬 본문은 frontmatter를 제외하고 양끝 공백을 제거했다. 공통 정책은 실제 `hooks/ttak.cjs`의 `compose` 반환값을 측정했다. 도구 정의는 로컬 dispatcher에 initialize와 initialized를 전달한 후 tools/list 결과를 측정했다. 모델이나 외부 MCP 서버를 호출하지 않았다.

도구 정의의 원문 크기가 호스트가 매 요청에 모델에 전달하는 크기와 같다고 주장하지 않는다. 호스트의 도구 지연 로드·변환·필터링은 별도다. `ttak off`는 공통 정책 주입을 끄며, 설치된 설명 스킬이나 MCP 도구 정의 자체를 제거하는 설정은 아니다.

## 실제 209 Claude 전문가 설명

| 검토 패킷 | 전체 byte | 첫 줄 실행·검토 지침 | 요청·사실·최종 답변 data JSON | submission 객체 JSON |
|---|---:|---:|---:|---:|
| 사실 검토 | 5,904 | 3,234 | 399 | 2,109 |
| 최종 검토 | 21,131 | 2,613 | 6,008 | 12,347 |

전체에는 나머지 envelope와 구분자도 포함되므로 세 부분의 합계와 다르다. 실제 explanation_packet 반환의 prompt를 측정했으며, data에 있는 사용자 질문·사실 답변·최종 문안은 지침과 구분했다. 최종 submission 객체에는 도구 이름과 입력 스키마가 포함된다.

부모 native 입력에서 설명 스킬 본문이 두 번 나타났다. 이는 이 세션의 관측이며 모든 실행에서 항상 두 번 주입된다는 뜻은 아니다. 부모 hook 추가 문맥은 각각 3,645 / 3,871 / 190 / 4,062 byte였다. 두 검토자의 SubagentStart 추가 문맥은 3,022 / 3,496 byte였고 각각 2,303 byte의 하위 공통 정책을 포함했다. 서로 다른 모델 문맥의 크기를 하나의 프롬프트 크기로 합치지 않는다.

| 관측 범위 | 모델 응답 수 | 누적 입력 token | 누적 출력 token | 합계 token |
|---|---:|---:|---:|---:|
| 전문가 질문과 내부 검토자 2개 | 13 | 366,894 | 6,127 | 373,021 |
| 선행 스킬 활성화 | 3 | 90,699 | 1,023 | 91,722 |
| 같은 대화 전체 | 16 | 457,593 | 7,150 | 464,743 |

전문가 질문의 부모 모델 응답별 입력은 36,839–43,783 token이었다. 누적 입력에는 호스트 기본 문맥, 도구·대화 기록, 캐시 생성·읽기가 포함된다. 373,021 token을 새로운 주입 지침 크기나 한 번의 context 크기로 해석하면 안 된다. 지침만의 정확한 모델별 token 수나 실제 청구 비용은 이 측정으로 분리하지 않았다.

## 설계 판단

현재 확인된 직접적인 사실 오류는 설명 영역에 집중되어 있다. Ponytail·진행 안내까지 전부 결함으로 불합격한 것은 아니다. 그러나 설명 지침, 도구 스키마, 실행 안내와 여러 모델 응답이 누적된 구조에서도 알려진 사실 오류가 승인됐다. 현재 설명 설계가 추가 복잡성과 사용량에 상응하는 정확성 효과를 확보하지 못했다는 판단은 타당하다. 정보량 과다가 사실 오류의 직접 원인이라는 인과 관계는 검증하지 않았다.

다음 설계 검토에서는 공통 정책과 기능별 지침을 구분하고, 필요한 경로만 제공하며, 반복되는 실행·반환 형식 설명을 줄일 수 있는지 확인해야 한다. 기존 검증 경계를 삭제하거나 모델의 동의를 사실 근거로 간주하는 방식으로 축소해서는 안 된다. 이 문서는 측정·판단 기록이며 재설계 완료나 출하 합격 선언이 아니다.

근거는 `.superpowers/injection-size-static-210.json`, `.superpowers/injection-size-native-210.json`, `.superpowers/injection-size-packets-210.json`과 원래 209의 collection/completion audit다. 측정 중 tools/list를 initialized 알림 전에 요청해 거부된 로컬 시도가 한 번 있었으며, 정상 초기화 순서로 수정했다. 모델 재실행은 없었다.
