# 완화책의 실행 순서 명시: 로컬 변경 67과 진단 68 준비

상태: 로컬 변경 67 뒤 승인된 진단 68을 1회 실행·검토했다. 누적 697회,
진단 잔여 3회, 전체 비교용 516회 미사용. 설치된 제품에는 연결하지 않았다.

## 진단 68 결과

세션 `01a08723-9b72-7560-8498-afde388c62a4`에서 Luna/high와 정확한 입력을 확인했다.
약 26.5초 뒤 정상 종료했고 하위 프로세스 0개로 정리했다. 실제 MCP 호출은 1회이며,
네이티브 `exec` wrapper 2회는 도구 검색과 호출·결과 전달이었다. 코드 내용을 검토했고
별도 셸·파일·네트워크 작업은 없었다. 도구의 텍스트와 구조화된 응답 모두 재계산과 일치했다.

최종 답변은 스냅샷 획득과 조건 검사까지 포함한 직렬 조정을 설명하고, 이후 참가자가
이전 결과를 읽어 근무를 유지하는 동작과 동시성 비용, 모든 참가자의 동일 규칙 준수를
명시했다. 진단 66의 격리 수준 혼동 표현은 없었고 실제 DB·SQL·잠금·재시도 검증도
주장하지 않았다. 수동 검토에서 원래 과제의 필수 3항목과 품질 2항목을 충족했다.

판정은 `single_diagnostic_content_pass_manual_review`다. 이는 조정에 사용한 과제의
단일 관측으로, 문단 추가의 인과 효과나 반복 개선, 기본/원본 대비 개선, 설치 제품의
합격을 입증하지 않는다. 수집 당시의 미검증 플래그를 덮어쓰지 않고
`.superpowers/luna-scenario-68/operator-review.json`에 사후 판정을 별도로 기록했다.
누적 세부는 Claude 412회, Codex 285회다. 재시도는 하지 않았다.

## 분석과 변경

진단 66의 Luna는 올바른 입력을 만들고 정확한 계산 결과를 받았지만 최종 답변에서
실제 직렬 실행과 serializable 실행을 같은 읽기 순서를 보장하는 대안처럼 묶었다.
현재 스킬에는 이미 검증하지 않은 실행 순서를 보장하지 말고 선택적 대안을 추가하지
말라는 지침이 있다. 같은 규칙을 스킬에 반복해서 추가하지 않는다.

`finite-scenario-render.cjs`의 완화책 뒤에 두 문단을 추가했다.

- 실제 참가자 ID로 스냅샷 획득 → 조건 검사 → 조건이 참이면 쓰기 → 완료 → 다음
  참가자의 스냅샷 획득 순서를 표시한다. 성공을 주장하는 조건은 모든 직렬 순서가
  불변식을 유지하면서 동시 시작 실행에 위반이 있는 경우로 유지한다.
- 모든 스냅샷을 먼저 얻고 커밋만 순서대로 처리하는 경우에는 이미 계산한 위반 실행이
  남는다고 설명한다. 이름이 붙은 격리 수준이나 잠금 구현의 동작을 검증한 것은 아님을 명시한다.

이는 도구 출력의 설명 보완이며 새 계산 알고리즘이나 의미 검증기가 아니다. 모델이
이 내용을 보존할지는 아직 모른다. Haiku·Luna에서 개선됐다고 주장하지 않는다.
계산 로직, 반환 facts, 제품 스킬과 원래 과제의 품질 기준은 변경하지 않았다.

## 검증과 보존

관련 테스트 26개가 통과했다. 세 참가자의 순서를 입력으로부터 구성하는지, 안전한
입력에서는 위반이나 완화책을 주장하지 않는지, 직렬 실행도 실패하는 로직을 완화책으로
인증하지 않는지 확인했다. 기존 MCP 통신·응답 감사 검사도 통과했다.

이전 렌더러와 계산 모듈을 `.superpowers/mitigation-boundary-67/`에 보존했다. 이전
렌더러 해시가 진단 64·66의 고정 입력과 같음을 확인했다. 실제 66 입력에 대해 수정 전후
facts가 동일하고 설명 문단 두 개만 추가됨을 `comparison.json`에 기록했다.
기존 진단의 재계산은 해당 과거 버전을 사용해야 한다. 기존 실행기의 해시 검사는 이제
변경을 감지하므로 우회하거나 과거 plan을 덮어쓰지 않는다.
