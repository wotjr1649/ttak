# Haiku·Luna 첫 출하 검증

2026-09-09 사용자가 확정한 새 모델 조건이다. 기존 Sonnet 실험과 중단된 진단 49는
역사적 기록으로 보존한다. 이 문서는 새 검증의 모델 조건과 추가 합격 기준을 정하며,
기존 과제의 필수 품질·원본 비교·실제 전달 검증을 낮추지 않는다.

## 고정 조건

| 호스트 | 모델 | 추론 설정 |
|---|---|---|
| Claude Code | `claude-haiku-4-5-20251001` | thinking 활성화, `MAX_THINKING_TOKENS=8192`; effort 해당 없음 |
| Codex CLI | `gpt-5.6-luna` | `high` |

Haiku의 날짜 포함 ID와 effort 미지원은 [모델 공식 문서](https://platform.claude.com/docs/en/models/haiku-4-5/overview),
고정 thinking 설정은 [Claude Code 공식 문서](https://code.claude.com/docs/en/model-config)를
2026-09-09 확인했다. 8192는 이번 시험의 사전 지정 상한이며 실제 사용 토큰이나
두 호스트의 연산량 동등성을 뜻하지 않는다. 설정 요청과 실제 적용 증거를 구분한다.
최초 네이티브 점검에서 모델·설정·구독 접근을 확인하기 전에는 검증 완료로 기록하지 않는다.

각 호스트의 기본·원본·TTAK에 동일한 모델과 추론 설정을 적용한다. 기존 로그인만
사용하며 추가 사용·API 과금·대체 모델 없이 진행한다. 설정은 자식 CLI 호출에만 전달한다.
사용자의 기본 모델이나 전역 설정을 바꾸지 않는다. 실패 결과는 보존하고 자동 재시도하지 않는다.

## 합격 판정

기존 `tests/release/cases.json`의 16과제, 모든 hard/quality 항목, 2반복, 3조건,
2호스트를 유지한다. 기존 Sonnet 결과를 Haiku 관측으로 전환하지 않는다.

1. 양 호스트에서 네 기능 및 혼합 과제의 모든 후보 필수 품질을 통과한다.
2. 동일 모델의 해당 원본 대비 기능별 미해결 중대 퇴보가 없어야 한다.
3. 적어도 한 기능에서 기본 모델 대비 실질적인 개선이 두 독립 반복에서 관측돼야 한다.
   양 호스트에서 각각 개선을 입증한다. 어느 기능이 개선됐는지 호스트별로 공개한다.

실질적 개선은 사전에 고정된 과제의 기능 정확성, 독자 적합성, 필요한 복잡성 판단,
또는 복귀 시 상태·다음 행동의 정확성에서 확인한다. 필수 항목의 실패→통과, 혹은
고정 quality 항목에서 사용자의 이해·판단·실행에 영향을 주는 구체적 결함의 해소가
해당한다. 단순 말투 선호, 길이 감소, 검토자 동의만으로 개선으로 세지 않는다.
같은 과제의 두 반복에서 같은 개선 항목을 확인하고, 해당 기능의 다른 과제에 있는
필수 실패나 중대 퇴보로 상쇄하지 않는다. 기준 모델도 이미 충족하면 동률을 허용하지만
동률만으로 추가 개선 기준을 통과하지 않는다. 전체 결과와 불리한 비교도 함께 공개한다.

## 실행 순서와 상한

먼저 새 Haiku 설정의 네이티브 접근·실제 전달을 최대 1회로 확인한다. 연결 점검은
제품 품질 시험이 아니다. 이어 원인에 작용하는 구현 변경을 선정하고 알려진 실패,
정상 대조, 조정에 쓰지 않은 과제로 최종 답변을 확인한다. 이 진단 전체는 남은 24회
안에서 별도 사전 장부로 배정한다. 중단된 진단을 다시 여는 방식으로 진행하지 않는다.

전체 비교는 후보의 알려진 결함이 해소된 후 새로운 입력 freeze로 시작한다.
subject/activation은 baseline 88 + original 172 + TTAK 128 = 388회,
비교 채점 배정 128회를 포함해 최대 516회다. 내부 요청·캐시·토큰·시간은 별도 계수다.
추가 검토를 제품 경로에 통합하면 그 호출도 다시 계산해야 하며, 이 상한이 자동 증가하지 않는다.

현재 `tests/release/low_models.py`는 새 모델용 명령·환경과 기존 과제를 재사용하는
별도 계획을 구성한다. 모델 실행이나 프로필 수정은 하지 않는다. 네이티브 실행·감사와
제품 개선·전체 합격은 아직 별도의 미완료 작업이다.

진단 51에서 새 Haiku 설정으로 네이티브 연결 1회를 실행했다.
`.superpowers/haiku-setup-51/audit.json`은 Claude Code `2.1.266`, 날짜 포함 모델 ID,
정확한 합성 입력 전달과 thinking 블록 존재를 확인한다. 프로세스 정리도 확인했다.
세션 로그에 thinking budget 수치가 없어 `8192`는 요청값으로만 기록하며 실제 상한을
독립 검증했다고 주장하지 않는다. 숨겨진 thinking 본문은 출력하거나 별도 복사하지 않았다.
추가 모델 1회로 누적 677회(Claude 398, Codex 279), 진단 잔여 23회가 됐다.
모델 설정 테스트 6개와 기존 release 테스트 37개가 통과했다. 제품 품질 합격은 아니다.

후속 [설명 진단 52·53](LOW_MODEL_EXPLANATION_DIAGNOSTICS.ko.md)에서 기존 본문과 사건 표
변경안을 Haiku로 각각 1회 시험했다. 두 답변 모두 교차 읽기를 부정하는 내부 모순이
있어 실패했다. 변경안은 정확히 복구했고 Luna 재시험은 하지 않았다. 최신 누적은
679회(Claude 400, Codex 279), 진단 잔여 21회이며 전체 비교는 아직 시작하지 않았다.

## 상위 모델 후속 검증

Haiku·Luna 합격 후보의 파일 해시와 과제·판정 기준을 보존한 뒤 Opus·Sol을 추가로
검증한다. 당시 지원되는 정확한 모델 ID·추론 설정·구독 접근을 확인하고, 동일한
16과제×2반복×3조건×2호스트 비교를 별도로 계획한다. 같은 활성화 구조라면 516회가
필요한 잠정 산정이며 이번 잔여 예산에는 포함하지 않는다. 구체적 실행 상한을 정하기
전에는 시작하지 않는다. 상위 모델 결과로 하위 모델의 실패를 대체하지 않는다.

## 비교 입력 고정 도구

`tests/release/low_study.py`는 새 모델 조건의 계획·과제·판정 기준과 실제 제품 입력을
별도로 저장하고 검증한다. 기존 Sonnet freeze를 수정하지 않는다. 제품 manifest,
hook과 정책·스킬, 고정 원본, fixture와 현재 수집 준비 코드의 원본 바이트를 보존한다.
변조된 manifest의 파일 목록을 신뢰하지 않고 현재 코드가 정한 입력 목록과 대조한다.
빠진 과제, 모델 변경, 바뀐 입력 복사본, 추가 지침 파일, 링크와 비정상 파일 트리를 거부한다.

준비 snapshot `.superpowers/low-model-preparation-58`을 생성하고 검증했다. 192개
계획과 516회 산정은 유지한다. **설명 결함이 남은 후보의 준비 기록이며 출하 합격이나
전체 비교 실행 승인으로 간주하지 않는다.** 향후 실제 수집기·네이티브 설치 전달·런타임
버전을 확정하고 알려진 결함을 해결한 뒤 새 실행 snapshot이 필요하다. 실험용 독립
검토 모듈은 현재 제품에 연결되지 않았으며 이번 제품 입력에 포함됐다고 주장하지 않는다.

작업 트리 루트에서 기존 Python으로 실행한다. 두 명령 모두 모델 호출과 프로필 변경은 없다.

```powershell
& 'C:\Users\js\AppData\Local\Python\pythoncore-3.14-64\python.exe' -B tests/release/low_study.py --freeze .superpowers/<new-study-directory>
& 'C:\Users\js\AppData\Local\Python\pythoncore-3.14-64\python.exe' -B tests/release/low_study.py --verify-freeze .superpowers/low-model-preparation-58
```

첫 명령의 `<new-study-directory>`는 아직 존재하지 않는 디렉토리 이름으로 바꾼다.
이미 생성한 snapshot을 덮어쓰거나 검증을 위해 재생성하지 않는다.
`test_low_study.py`의 6개 검사는 실제 로컬 freeze 생성·검증, 덮어쓰기·범위 밖 경로,
manifest 삭제를 통한 변조 은폐, 모델·과제 변경, 원본 복사본·추가 지침, 현재 입력 변경을
확인했다. 모델 품질 테스트가 아니다. 진단 호출은 추가하지 않아 누적 684회와 잔여 16회는 유지한다.
