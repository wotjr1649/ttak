제품 요구를 분리했다고 해서 현재 알려진 오류가 해결되거나, 진단의 중단 조건이
소급 취소되지는 않는다. 향후 다른 설계는 별개의 근거·변경·검증을 갖춰야 하며,
이름이나 실행 디렉토리만 바꿔 중단된 효과를 다시 실행하지 않는다.

## 실제 제품 경로

두 플러그인 manifest, `hooks/hooks.json`, `hooks/ttak.cjs`, 정책과 스킬을 대조했다.
현재 설치 경로는 정책 주입과 `ttak-review`/`ttak-explain` 스킬을 제공한다. 이들 진입점에
검토 실험 모듈의 호출은 연결돼 있지 않다. 따라서 검토 모듈을 보류하는 것과 이미
설치된 제품 기능을 제거하는 것은 다른 작업이다. 이번에는 어느 파일도 제거하지 않았다.

현재 `ttak-explain`은 이미 코드 요청이 없으면 개념적 예제를 우선하도록 안내한다.
따라서 “SQL을 쓰지 말라는 지침을 추가하자”는 제안은 새 해결 메커니즘이 아니다.
SQL 답을 본문에 넣거나 알려진 과제를 빼는 것도 현재 결함의 해결로 인정할 수 없다.

전문가 설명 과제는 write skew, 두 의사 예제, 유효한 해결책과 trade-off를 요구한다.
SQL 코드 자체는 요구하지 않는다. 모델이 제시한 SQL과 동작 설명이 잘못됐기 때문에
회귀 판정에 포함됐으며, SQL 지원을 새 제품 요구로 확대한 것이 아니다.

## 진단 49가 증명한 것과 증명하지 못한 것

관측된 것은 첫 근거 검토의 주장 누락이다. 최종 두 역할의 답변, 수정 결과, Codex
품질은 실행하지 않았으므로 실패했다고 채점할 수 없다. 첫 단계의 중단을 전체
설계의 불가능성으로 확대하면 안 된다. 반대로 미실행 단계가 구제할 것이라고
가정해 같은 실행을 계속하는 근거도 없다.

이번 로컬 점검은 추가 제어 흐름 문제를 확인했다. 진단 49의 근거 보고에는
`not_established`가 4개 남아 있다. `mergeRoles`는 근거 보고를 수정하지 않으며,
충돌·겹침으로 먼저 중단하지 않더라도 이 4개 때문에 `unresolved`를 반환한다.
`reviewByRoles`는 `repairable`에서만 수정 호출로 진행한다.

저장된 실제 근거 보고에 두 개의 **명시적으로 합성한 문맥 보고**를 결합했다.

| 로컬 제어 흐름 입력 | 실제 코드 반환 |
|---|---|
| 추가 발견이 없는 합성 문맥 보고 | unresolved, 수정 입력 없음 |
| U014를 발견했다고 가정한 합성 문맥 보고 | unresolved, 수정 입력 없음 |

이는 문맥 모델을 실행한 결과가 아니며, 오류 탐지나 수정 품질의 증거도 아니다.
소스의 분기와 두 로컬 입력으로 확인한 것은 **문맥 역할이 그 문장을 찾는다고 가정해도
현재 실행부가 자동 수정까지 진행하지 않는다는 것**이다. 이 추론은 현재 근거 보고를
그대로 유지하는 경로에 한정된다. 다른 설계의 가능성까지 부정하지 않는다.
`not_established`를 사실 오류로 바꾸거나, 없애거나, 검증됐다고 처리하지 않았다.
기록은 `.superpowers/release-path-50/result.json`에 있으며 원본 보고와 모듈 해시를 담는다.

## 외부 방법을 확인한 범위

공개 원 논문 소개·초록을 확인했다. 패키지 설치나 API 실행은 하지 않았다.
[FActScore](https://aclanthology.org/2023.emnlp-main.741/)는 답변을 atomic facts로 나누어
근거가 뒷받침하는 비율을 평가한다. [SAFE](https://arxiv.org/abs/2403.18802)는 장문 응답의
사실을 분리하고 검색을 활용해 평가한다.
[VeriScore](https://aclanthology.org/2024.findings-emnlp.552/)는 검증 가능한 주장에 초점을
맞추며 과제별 평가 결과가 다른 과제로 그대로 이어지지 않을 수 있음을 보고한다.

이 방법들은 평가 설계의 참고 자료다. 이 자료에서 TTAK의 고정 모델·현재 설명 과제에
대한 직접 검증은 확보하지 못했다. 또 다른 주장 추출기나 검색형 평가기를 붙이면 이번
누락과 최종 답변의 결함이 해결된다는 근거로 사용하지 않는다. 문헌 전체를 검토했거나
가능한 해결책이 없음을 증명했다고 주장하지 않는다.

## 권고와 재개에 필요한 근거

**현재 조건을 유지한 채 실행을 정당화할 새 구현 후보를 이번 재평가에서 선정하지 못했다.**
이번 판단에 필요한 사용자 설정 변경이나 추가 승인은 없다. 제품 코드·스킬·후크,
기존 중단 장부와 freeze를 보존하고 새 모델 시험과 검토 시스템 확대를 보류한다.
문서와 제어 흐름 점검을 완료했지만 제품 정확도가 개선됐다고 표현하지 않는다.

새 모델 시험은 다음이 함께 구체화될 때 제안한다.

1. 위의 실패한 접근과 실질적으로 다른 변경 및 그것이 결함에 작용할 근거.
2. 최종 답변의 정확도·완결성을 판정할 관측 방법. 검토자 동의나 문단 수만 쓰지 않음.
3. 알려진 실패와 정상 대조, 조정에 쓰지 않은 입력에 대한 시험 계획과 전체 호출 장부.
4. 원래 네 기능과 비교 기준을 유지하며 실패 기록·중단 조건을 보존하는 실행 경로.

현재 이 조건을 갖춘 구체적 제안이 없으므로 남은 호출을 배정하지 않는다. 사용자가
새로운 요구를 정해야만 한다고 떠넘기거나, 막연한 예산·모델 변경을 요청하지 않는다.
그러한 변경이 실제로 필요한 근거가 생기면 영향과 대상이 정해진 제안으로 별도 다룬다.
