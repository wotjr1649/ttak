## 독립 검토와 후보 판단

검토된 합성 사례와 기준·계수만 전달해 에이전트 3개에 증거 감사, 개입 설계,
반론·비용 검토를 맡겼다. 파일 편집이나 네이티브 실행은 맡기지 않았다.
각 역할에 한 차례 반론을 전달했고 root가 다음과 같이 통합했다.

- 실제 DB/barrier 실행을 새 필수조건으로 삼자는 의견은 제외했다. 원래 과제는
  전문가 설명이며 정확한 유한모델 실행 예시는 이미 제공됐다.
- 자유로운 최종 문장의 결정론적 보장 부재만으로 모든 후보를 배제하는 의견은
  제외했다. 실제 다른 개입의 경험적 품질 개선도 원래 목표에 부합한다.
- 진단 두 번으로 16과제·두 반복을 충족한다는 해석은 제외했다. 전체 비교의
  착수에는 알려진 결함 해소, 설치 전달, 새 입력 freeze 등 별도 근거가 필요하다.
- 기존 host의 model-request/response-emission 지점에 어댑터를 붙일 수 있다는
  설계의 가정은 확인된 기능으로 취급하지 않았다. 짧은 주장 ID가 토큰·지연을
  줄인다는 의견 역시 측정 근거가 없어 성과로 채택하지 않았다.

검토한 한 후보는 **초안의 구체적 주장 → 유한모델 대조 → 불일치 피드백 →
동일 호스트의 최종 설명**이다. 기존 계산기처럼 정답을 먼저 제공하는 것과 달리,
모델이 실제로 한 잘못된 주장에 피드백을 준다는 개입 가설은 있다.

그러나 현재 구현 가능한 변경으로 선택하기에는 다음 두 전제가 빠져 있다.

1. `relation_id`·극성·범위 필드가 맞더라도, 연결한 자연어 문장은 그 관계를
   부정할 수 있다. 기존 span/claim 모듈은 인용 위치와 형식·완전성 등을 검사하며,
   문장의 의미를 독립적으로 대조하는 구현을 제공하지 않는다. 모델이 스스로
   올바른 필드를 제출했다는 사실로 문장의 사실성을 인증할 수 없다.
2. 실제 제품은 manifest, 설명·리뷰 스킬과 SessionStart/SubagentStart/
   UserPromptSubmit hook 경로다. 실험 계산기는 이 경로에 연결되지 않았다.
   제안된 최종화 어댑터의 구체적 설치 지점과 최종 답변까지의 적용 근거가 없다.
   기존 정적 host 계약 분석을 새 실동작 검증으로 승격하지 않는다.

따라서 새 스키마·렌더러·검토기를 추가하는 것만으로 기존 실패와 다른 후보가
완성됐다고 볼 수 없다. 두 전제를 가정한 코드를 만들거나 같은 진단을 다시 여는
대신 설계 가설로 남겼다. 이는 구현을 시도한 뒤 테스트에 실패했다는 기록이 아니다.
제품 버전, 스킬, hook, MCP 등록 및 기존 실패 장부를 변경하지 않았다.

## 남긴 단 하나의 판별 검사와 재진입 조건

다음 검사는 **실제 제품의 주장 피드백 경로에 대한 정상·모순 쌍 검사**다.
새 연결 지점과 의미 대조 구현이 구체화되면 먼저 모델 호출 없이 수행한다.

- 합성 입력: 초기 `A=B=true`; `T1`은 `B`를 읽고 `A=false`를 쓰며, `T2`는
  `A`를 읽고 `B=false`를 쓴다. 두 snapshot은 첫 commit 전에 얻는다.
- 정상 초안은 두 교차 read/write 관계와 서로 다른 write 대상을 구분한다.
  모순 초안은 같은 올바른 claim ID·극성 필드를 유지한 채, 본문에서 상대가
  읽는 값을 어느 쪽도 쓰지 않는다고 부정한다. 두 초안의 구조화 필드를 같게
  둬서 카드만 검사하는 구현을 구별한다.
- 실제 제안 제품 경로가 정상 초안을 오탐하지 않고 모순 **본문**을 구별해
  해당 위치의 구체적 피드백을 같은 응답 경로에 전달해야 한다. claim ID만
  검사하거나 정답 카드를 표시하는 결과, 원문을 무시한 오류 종료는 통과가 아니다.
- 로컬 통과는 이 연결의 검사 근거다. 모델이 피드백을 받아 요청된 설명을
  완성하는지는 이후의 별도 네이티브 관측이며, 로컬 검사로 대신할 수 없다.

현재는 그 의미 대조 구현과 설치 연결이 없어 이 검사를 실행하지 않았다.
실행 가능한 검사 명령이나 지원되지 않은 host API를 만들어 적지 않는다.
재진입에는 이 두 지점의 구체적 코드와 관측 가능한 피드백 경로가 필요하다.
이 조건은 해당 설계 가설을 위한 것으로 다른 경험적 개입을 배제하는 보편 요건은 아니다.

로컬 쌍 검사의 모델 비용은 0이다. 그 뒤 네이티브 검토를 하려면 새로운 고정 계획에
후보·입력·현재 버전·런처 검증·정확한 모델·구독/추가 과금 조건·호출 상한·권한을
명시해야 한다. CLI 실행 수 외에 도구 왕복과 continuation의 내부 모델 요청·토큰·시간도
별도로 계수한다. 잔여 2회를 자동 실행 권한으로 해석하지 않는다.
첫 실패 또는 미확인에서 후속 실행을 멈추고, 516회를 탐색으로 전용하지 않는다.
