# 출하 준비 83

상태: 승인된 로컬 준비를 마쳤고 네이티브 장부는 중단됐다. 현재 후보
`0.2.0-rc.11+codex.20260910175056`의 출하 판정은 **No-Go**다. 이 문서는 로컬 구현·설치·검사와
실제 모델 품질의 증거를 구분한다. 이전 rc.10의 Q1 실패를 새 후보의 통과로 이월하지 않는다.

제품 경계는 Haiku/Luna, 양쪽 CLI의 플러그인 흐름, 네 기능과 원래 품질 기준이다.
새 후보는 `scenario_review`의 근거를 사용한 설명이 끝날 때 같은 모델이 한 번 더
전체 설명을 대조하도록 요청한다. 오류가 정규식에 걸리지 않아도 개입하지만, 이 과정은
정확성 보증이 아니다. 정상 설명의 불필요한 수정, 토큰과 지연도 실제 실행에서 확인한다.

세션별 저장 내용은 이름을 순번으로 바꾼 유한 계산 모델과 턴 처리 상태다. 원래 식별자,
초안, 사용자 프롬프트, transcript 경로는 저장하지 않는다. 새 사용자 턴·재개·종료 시
근거를 비우고, 소비한 근거로 교정을 반복하지 않는다. OFF는 개입하지 않는다.
파일 잠금·링크·변조·크기 제한·만료로 근거를 사용할 수 없으면 검증 성공으로 보고하지 않는다.

훅 경계는 공식 [Codex 문서](https://learn.chatgpt.com/docs/hooks)와
[Claude Code 문서](https://code.claude.com/docs/en/hooks)를 2026-09-11 확인했다.
`PostToolUse`는 도구 출력을 바꾸지 않고 성공한 로컬 계산 결과를 대조한다.
`Stop`의 정상 continuation을 사용하며 호스트의 신뢰 절차를 유지한다.

현재 로컬 관측은 Windows Node 24.19.0의 Node 217개, Python 3.14.6의 78개,
conformance selftest 통과다. Ubuntu/Windows × Node 22/24 전체 검사를 CI에 구성했지만
원격 CI 실행 결과는 아직 없다. 모델 호출·원격 게시 없이 실행하는 명령은
`node scripts/test-local.cjs`다. Python 실행 경로는 필요하면 `TTAK_TEST_PYTHON`으로 지정한다.
CI는 [공식 setup-python 사용법](https://github.com/actions/setup-python)을 확인해 Python 3.14를
명시했다. 플러그인 런타임 의존성은 추가하지 않았다.

새 실행 상한은 네이티브 요청 12회(통합 4, 품질 8)다. 시작 누적은 707회
(Claude 421/Codex 286)이며, 중단된 80의 미사용 3회는 재사용하지 않는다.
첫 후보 실행·품질 실패 시 뒤 후보 행은 미실행으로 남기고 독립적인 로컬 출하 준비를 계속한다.
전체 비교 192 subjects/516 requests는 별도 확인 전 실행하지 않는다.

## 실제 실행과 중단 원인

| 요청 | 관측 | 판정 |
|---|---|---|
| `01.haiku.off` | 정상 훅이 `ttak off`를 소비하고 `enabled:false` 저장, 모델 턴·토큰 0 | 통합 통과 |
| `02.haiku.on` | 새 CLI 프로세스에서 `ttak on` 소비, `enabled:true` 저장, 모델 턴·토큰 0 | 통합 통과 |
| `03.luna.off` | 이전 플러그인의 활성 이벤트를 감지해 수집기 중단, 세션에 assistant 응답 0, `turn_aborted` | HARNESS_ERROR |
| 나머지 제어 1행·품질 8행 | 호출하지 않음 | UNRUN |

현재 누적은 **710 requests: Claude 423/Codex 287**다. 제어 요청도 계수하는 기존 규칙을
따랐다. Codex 중단 요청의 토큰 사용량은 보고되지 않았으므로 0으로 확정하지 않는다.
83 장부는 3회 사용·9회 미실행으로 닫았고, 80의 미사용 3회와 전체 비교 516회도 그대로다.

Codex `0.154.0`은 `-c plugins."ttak@ttak-release".enabled=false`의 따옴표를
키 이름 일부로 처리했다. 실제 `config/read`에 기존 `ttak@ttak-release`는 `true`,
따옴표가 포함된 별도 키는 `false`로 함께 나타났다. 이전 플러그인이 실제로 활성 상태여서
수집기의 중단은 올바른 동작이었다. 정상 설정을 우회하거나 검사 기준을 완화하지 않았다.

`pluginSelectionOverride`는 고정 `plugins` 키의 TOML 값 안에 식별자를 넣는다.
`verifyPluginSelection`은 호스트가 해석한 전체 플러그인 집합을 비교한다. 수정된 인자로
모델 없는 `config/read`·`hooks/list`를 실행해 이전 두 플러그인이 비활성이고 후보의
신뢰된 여덟 핸들러만 활성인 것을 확인했다. 실행 전 이 조회를 통과해야 다음 품질 과제를
시작할 수 있다. 실패했던 네이티브 요청은 재실행하지 않았다.

## 출하 범위별 근거와 남은 공백

| 범위 | 이번에 확인한 내용 | 아직 필요한 증거 |
|---|---|---|
| 개발 | 기존 재사용·CSV·재시도·안전한 축소 fixture와 보존 검사를 전체 회귀에 포함 | 현재 후보와 Haiku/Luna의 4개 개발 과제 결과 |
| 검토 | 필요한 계층·이미 작은 코드·중복 제거의 범위와 정책, 3개 과제·기존 판정기를 검토 | 원본 대비 중대 퇴보가 없다는 실제 비교 |
| 설명 | 계산 근거 수집과 턴 격리, 정확한 도구 출력 대조, 한 번의 Stop 요청, 최대 입력·연결 파일·변조 반례 통과 | 전문가·정상·미사용 사례의 완성 답변 H/Q, 정상 답변 변경과 추가 비용 |
| 진행·혼합 | 중단 후 복귀·반복 실패·완료와 두 혼합 과제의 기존 기준 유지, 정책·스킬 검사 통과 | 사용자 요청을 이어 가는 실제 모델 동작과 양 호스트 개선 |
| 설치·제거 | 양쪽 정상 CLI로 rc.10 설치 → rc.11 업데이트 → 제거, 설치 바이트 대조, Codex 훅 신뢰 8개 검토 | 수정된 수집기로 Codex 제어·실제 교정 완료 |
| 배포 준비 | 전체 검사 진입점·CI 확대, manifest 버전 일치, MIT와 귀속 고지 보존, 검토용 로컬 패키지 | 원격 CI, 배포 채널의 등록 검증, 전체 비교 합격·게시 승인 |

최초 신뢰 준비에서 Windows의 기본 `cp949` 디코딩 오류가 발생해 UTF-8을 명시했다.
그다음 엄격한 훅 검사가 `SessionEnd`의 선언 5초와 실제 적용 3초 차이를 차단했다.
선언을 3초로 맞춘 뒤 동일 검사로 여덟 핸들러를 확인했다. 초기 Node 테스트 명령도
동시성 상한이 없어 자동 검토에서 차단됐고, 안내된 상한 1을 적용했다.
차단·실패 기록은 성공한 검사와 별도로 보존했다.

작업용 설치와 마켓플레이스는 정상 CLI로 제거했다. 기존 플러그인 선택은 설치 전과 같고,
이번 신뢰 기록 여덟 개만 native `config/batchWrite`로 제거했다. 다른 설정이 보존됐음을
비교했다. 기존 Codex TTAK 저장 상태는 ON이며 수정 시각은 이번 작업 전인 2026-09-08 그대로다.
Claude 시험 데이터는 정상 제거됐고, Codex가 남기는 빈 `.notified` 표식은 실행 상태가 아니다.

## 다음 확인에서 제안할 진행

권고는 기존 경계 안에서 이 후보의 제한 검증을 계속하는 것이다. 의미 오류 해결이나
최적성은 아직 입증되지 않았으므로 전체 비교 516회를 바로 실행하지 않는다.
새 장부의 제안 상한은 12 requests다. 수정된 설정의 실제 조회와 설치 바이트 대조를
선행 조건으로 두고, OFF/ON 통합 4회와 고정된 품질 8회를 순서대로 수행한다.
품질 순서는 Haiku known1, Luna known1, Haiku unseen, Luna unseen, Haiku normal,
Luna normal, Haiku known2, Luna known2다. 어느 행이든 실행·전달·실질 품질에 실패하면
뒤 행을 미실행으로 남긴다. 같은 장부 재개나 516회 전용은 하지 않는다.

이 제안은 아직 새 실행 승인이 아니다. 이전 장부의 미사용 9회도 자동으로 옮기지 않는다.
정상 답변 변화·추가 시간·토큰을 포함해 8행을 통과해야 전체 비교 진입을 검토한다.
독립된 블라인드 채점과 기본·원본 대비 개선도 여전히 필요하다. 하나의 전문가 답변이나
로컬 검사 통과로 네 기능의 출하 합격을 대체하지 않는다.

기존 파일의 작업 전 바이트, 진행표, 설치·검사 로그는 이 worktree의
`.superpowers/release-preparation-83/`에 보존한다. 해당 디렉토리는 ignored이므로
HEAD만으로 재현된다고 주장하지 않는다. 전역 프로필 변경·push·publish는 수행하지 않는다.
