실행됐지만, 수정된 최종 설명의 Q1 정밀성이 실패해 출하 판정은 No-Go**다.

## 통합 범위와 로컬 검증

사용자의 통합 검증 진행 지시에 따라 [진단 86](NATIVE_DIAGNOSIS_86.ko.md)의 검토된
다섯 파일 패치를 제품 worktree에 반영했다. 두 manifest의 버전은 `0.2.0-rc.13`이다.
`hooks/scenario-evidence.cjs`는 실제 호스트가 전달한 JSON 문자열을 단일 text block으로
정규화한 뒤 기존 객체·배열과 동일한 엄격한 재계산 대조를 적용한다. 관련 테스트 두 파일은
문자열의 정상 경로, 잘못된 JSON·wrapper·다른 계산값의 거부, 실제 패키지 명령을 검증한다.

다섯 파일 모두 검토 사본과 바이트가 일치한다. 원문 진단 로깅은 제품에 넣지 않았다.
단일 text block·인자 키·재계산 결과 대조와 턴 격리·유효기간·파일 보호·한 번만 소비하는
제한을 유지했다. 문자열이라는 이유만으로 결과를 신뢰하지 않는다.

Windows에서 `scripts/test-local.cjs`를 실행해 **Node 221개(22개 파일), Python 78개,
conformance self-test가 통과**했다. skip은 없다. Node 검사는 동시성 1로 실행했다.
이는 이번 통합된 소스의 결과이며, 진단 86의 관련 검사 25개와 구분한다.

## 수정 전후 품질

첫 완성 답변과 교정 후 최종 답변을 비교했다. 초기 스냅샷을 읽는 두 의사, 서로 다른 행의
쓰기, 두 명 모두 당직에서 빠지는 불변식 위반과 Serializable 해결책은 설명했다.
그러나 핵심 구현·비용 설명의 오류가 남았다.

| 오류 계열 | 첫 완성 답변 | 교정 후 최종 답변 | 판단 근거 |
|---|---|---|---|
| SI 충돌 종류 | SI가 행 단위 read-write 충돌을 감지해 한쪽을 중단시킨다고 설명 | 같은 충돌 종류를 유지하고 교차 읽기·쓰기에는 행 단위 충돌이 없다고 설명 | SI의 쓰기 충돌 처리와 rw 의존성을 혼동 |
| SSI 탐지 | 위험한 의존성 구조를 cycle로 설명 | cycle 설명을 유지하고 commit 시점 탐지로 한정 | 실제 위험 구조·순서 조건을 부정확하게 설명 |
| 낙관적 방식의 비용 | 드문 충돌에만 비용을 낸다고 설명 | 충돌할 때만 비용을 낸다는 주장을 유지 | 의존성 감시 비용을 누락 |
| 잠금과 동시 실행 | 읽는 행을 잠그면 두 트랜잭션 중 하나가 기다린다고 단정 | 동시 실행 자체를 방지한다고 강화 | 잠금 모드·획득 순서 조건이 빠짐 |

PostgreSQL의 Repeatable Read는 SI를 제공하면서도 직렬화 이상을 허용한다.
Serializable의 감시에는 비용이 있으며 충돌에 따른 재시도 비용과 구분해야 한다.
[PostgreSQL 18 격리 수준 문서](https://www.postgresql.org/docs/18/transaction-iso.html)

PostgreSQL SSI는 인접한 두 rw 충돌의 위험 구조와 순서 조건을 사용하며, 실제 cycle이
없어도 중단할 수 있다. 이를 cycle의 commit 시점 탐지로 설명하면 구현 조건을 잃는다.
[PostgreSQL 18 SSI 구현 설명](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/storage/lmgr/README-SSI)

호환되는 잠금은 동시에 보유할 수 있다. 특히 공유 행 잠금은 서로 호환되며, 이후 충돌하는
연산에서 대기하거나 여러 행의 잠금 순서에 따라 교착이 생길 수 있다.
[PostgreSQL 18 명시적 잠금 문서](https://www.postgresql.org/docs/18/explicit-locking.html)
공식 근거 확인일은 2026-09-11이다.

Root 판정은 **H1·H2·H3·Q2 통과, Q1 실패, 종합 실패**다. 구체적인 불변식 예와
유효한 Serializable 해결책, 재시도·동시성 비용을 언급한 부분의 통과를 보존했다.
잘못된 충돌 탐지·비용 단정은 Q1에 반영했다. 이번은 root 검토이며 독립·블라인드 채점이 아니다.
지원하는 문구 검사가 최종 문제를 0개로 반환한 사실은 의미 정확성 합격이 아니다.
최종 답변에 근거와 일치한다는 자기평가와 체크 표시가 추가됐어도 실제 오류는 남았다.

## 시간·사용량·복원

설명 요청의 전체 프로세스 시간은 **55,289ms**였다. 첫 완성 답변에서 수정 답변까지 기록된
간격은 **28,220ms**, 마지막 교정 응답의 출력은 **2,362 tokens**다. 이는 단일 응답 연쇄의
관측값이며 교정 없는 대조군과 비교한 순수 추가 비용이나 평균 성능 추정값이 아니다.
출력 토큰은 호스트 집계값이므로 전부 사용자에게 보인 문장 분량이라고 해석하지 않는다.

설명 요청 전체 사용량은 입력 28, 캐시 생성 입력 16,494, 캐시 읽기 입력 27,204,
출력 4,428 tokens다. 출력 상세 thinking 2,078은 출력에 더하지 않는다.
정상 답변 행이 미실행이므로 정상 답변을 불필요하게 고치는 비율·비용은 알 수 없다.

시험 설치와 마켓플레이스를 정상 CLI로 제거하고 시험용 훅 신뢰 항목과 이번 생성 데이터를
복원했다. 설치 전후 목록이 같고 기존 설정·이전 ON 상태·기존 알림 마커가 보존됐다.
native 요청과 프로필 작업 모두 종료·Windows Job 정리를 확인했으며 잔류 프로세스는 0이었다.

이번 **5회(Claude 3, Codex 2)**를 포함해 누적 **727회(Claude 434, Codex 293)**다.
87 장부는 **5회 사용·7회 미실행으로 중단**했다. 이전 중단 장부도 유지한다.
전체 비교 **192개 subject·516회 요청은 전부 미실행**이다.

검토된 호스트 형식 수정은 로컬 제품 소스에 남기되 출하·게시하지 않았다. 고정 입력,

주장하지 않는다. 이전 진단 86의 별도 검토 패키지도 보존한다.
