# TTAK 재설계: 필요한 만큼의 방향성

상태: 재설계와 비활성 지침 초안 완료. 기존 runtime 교체, 설치, native 행동 검증과 출하는 미완료다. 이번 요청에 따라 원본 세 제품의 전 기능 대체를 목표에서 제외한다. 새 초안은 `design/ttak/`에 있고, 기존 실패 후보와 증거는 보존한다.

## 근거와 제품 판단

사용자가 지정한 Eric Provencher의 [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) 본문을 읽었다. 설명은 선택 상황을 좁혀 쓰고, 조건부 자료만 필요할 때 읽으며, 모델에게 과도한 고정 절차를 부과하지 않는다는 원칙을 채택한다. 완료 범위는 분명히 하되 불필요한 확인 단계는 추가하지 않는다. 이 글의 모델별 관찰을 기존 시험 모델 Haiku·Luna의 검증 결과로 간주하지 않는다.

현재 설명 경로는 짧은 지침을 제공하는 제품에서, 사실 검토·최종 검토·영수증·패킷·결과 재조회로 모델 작업을 통제하는 제품으로 커졌다. 이 복잡성을 들이고도 사실 오류가 승인됐다. 지침의 역할을 사용자에게 맞는 판단 방향과 필요한 맥락 제공으로 되돌린다. 문체를 강제하거나 모델의 모든 판단을 단계별로 대체하지 않는다.

방향성만으로 충분한 부분은 깊이, 말투, 정보 순서, 재사용 선호, 진행 안내 빈도다. 사용자 요구, 기존 동작, 사실의 중요한 조건을 보존하는 것은 결과의 요건이다. 권한·보안·파일 범위는 호스트와 실제 코드의 경계이며, 이를 프롬프트 축소 명목으로 변경하지 않는다.

## 브랜드와 선택

브랜드는 **Track · Trim · Adapt · Keep**, **딱 필요한 만큼. 딱 알아듣게. 딱 끝낸다.**를 유지한다. 네 항목은 매번 출력할 체크리스트나 고정 작업 순서가 아니다. 사용자가 체감할 판단 기준이다. 딱따구리 흉내, 반복 구호, 별도 강도 단계는 넣지 않는다.

| 출처 | 채택할 것 | 수용하지 않을 것 | TTAK에 반영하는 방식 |
|---|---|---|---|
| Ponytail | 기존 구현·표준 도구 재사용, 현재 가치 없는 복잡성 제거, 필요한 동작 보존 | lazy/ultra 페르소나, 한 줄·파일 수·순감소 줄 수 우선, 모든 호출자·전체 흐름을 매번 훑는 의식, 원래 요청보다 작은 기능을 임의로 납품 | Track·Trim의 선호와 필요 시 사용하는 `ttak-review` |
| Ponytail Review | 위치·현재 비용·대안이 있는 구체적인 단순화 검토 | 한 구현이면 무조건 불필요하다는 판정, 보안·호환성 맥락을 무시한 삭제, 억지로 찾는 지적 | 실제 요구와 사용 근거에 따라 복잡성이 필요한지 판단 |
| i-have-adhd | 다음 행동을 찾기 쉬운 설명, 의미 있는 진행 변화, 중단 후 목표 복귀, 정직한 완료 보고 | 사용자에게 ADHD가 있다고 가정, 매 턴 상태 반복, 목록 5개 상한, 무조건 시간 추정, 금지 표현 목록, 완료 뒤에도 새 행동 요구 | Keep에 통합. 긴 작업에서 필요한 시점에만 안내. 별도 ADHD 모드·스킬을 만들지 않음 |
| ELI5 | 독자와 목적에 따른 어휘·깊이·관점 조정, 유용한 예시 | 기본 독자 5세, 나이·관계별 고정 관념, 필수 비유·고정 설명 단계, 이해를 이유로 사실 정확성을 낮추는 규칙 | Adapt와 `ttak-explain`. 기본 독자는 해당 주제에 익숙하지 않을 수 있는 성인 |

지침은 영어로 새로 작성했다. 원본 문단을 합치지 않고 위 판단을 반영했다. 라이선스·저작자 표시는 기존 `ATTRIBUTIONS.md`와 고정 출처 목록을 유지하며, 새 배포 패키지에도 포함해야 한다.

## 새 구성과 주입 방식

| 구성 | 내용 | 로딩 결정 |
|---|---|---|
| `policy/core.md` | 짧은 브랜드 방향과 완료·근거·진행 선호 | 기존 ON/OFF 의미를 유지하는 선택형 core로 이행. OFF이면 core 0byte. ON이면 세션 시작에 core만 전달 |
| `skills/ttak-review/SKILL.md` | 불필요한 복잡성 검토 | 단순화 검토를 요청한 경우 선택. 일반 개발마다 별도 리뷰 강제 없음 |
| `skills/ttak-explain/SKILL.md` | 독자 목적에 맞는 설명 | 설명 요청과 관련 자료 이해에 선택. 코드 변경에 자동으로 설명 절차를 부과하지 않음 |
| 설명 전용 MCP·검토 에이전트 | 새 기본 제품에 없음 | 모델 합의에 기반한 의무 검토와 16개 설명 도구를 이행 대상에서 제외 |

발견용 스킬 이름·description에는 작은 비용이 남는다. 전체 스킬 본문은 필요할 때 읽고, core를 하위 에이전트마다 중복 주입하는 경로는 새 기본안에 포함하지 않는다. 호스트가 본문을 이미 유지하는 같은 세션에서 TTAK이 임의로 다시 읽으라고 요구하지 않는다. 재개·compaction 시 재주입 여부는 실제 호스트 문맥 유지와 함께 검증해야 한다.

`design/ttak/.codex-plugin/plugin.json`은 스킬 구성을 분석하는 비활성 초안이다. core hook은 아직 연결하지 않았으므로 이 초안을 설치하면 기존 ON/OFF가 구현돼 있다고 주장할 수 없다. Claude 패키징도 이행 작업에 남긴다. 새로운 스킬은 짧고 단일 목적이어서 빈 references 디렉터리나 불필요한 라우터를 만들지 않았다.

## 크기와 수용 기준

| 본문 | 기존 byte | 새 초안 byte | 감소 |
|---|---:|---:|---:|
| 메인 core | 3,645 | 690 | 약 81.1% |
| 설명 스킬 | 13,023 | 1,047 | 약 92.0% |
| 리뷰 스킬 | 2,289 | 983 | 약 57.1% |

frontmatter를 제외하고 양끝 공백을 제거한 UTF-8 크기다. core+설명 본문은 16,668 → 1,737byte다. 이는 지침 초안의 크기 차이이며, 전체 호출 토큰·가격·지연이 같은 비율로 줄어든다는 예측은 아니다. 기존 도구 정의는 Claude 53,599 / Codex 58,991byte였고 새 초안은 MCP 정의가 없다.

새 목표는 core 800byte 이내, 각 스킬 본문 1,200byte 이내, description 160자 이내다. 외부 표준의 의무 제한이 아니라 현재 단순한 제품 목적을 위한 설계 예산이다. 필요한 의미가 사라지면 우선 기능·조건을 확인하고 예산을 재검토한다. 참고 평균과 공식 권고는 [조사·평가 기록](TTAK_REDESIGN_RESEARCH_2026-09-14.ko.md)을 따른다.

## 확인할 결과와 이행 순서

1. 새 core·스킬·메타데이터의 구조, 크기, 선택 범위를 검증한다. 이번에 작성한 초안은 공식 구조 검사를 통과했다.
2. 기존 제어·저장 동작을 필요한 범위에서 재사용해 core ON/OFF와 호스트별 패키지를 연결한다. 무관한 설정·원본 기록·이전 실패를 보존하고 되돌릴 버전을 남긴다.
3. 옛 설명 전용 MCP·강제 검토 hook을 새 패키지에서 분리한다. 이는 실패를 통과로 바꾸는 수정이 아니라 제품 범위를 방향성 제공으로 바꾸는 이행이다. 호스트 권한과 보안 경계는 유지한다.
4. 개발·리뷰·설명·진행·비해당 요청의 대표 과제와 알려진 사실 오류를 기존 모델별로 한정 검증한다. 문장 일치·원본 기능 전체 재현·반복 우위는 요구하지 않는다. 실제 사실 오류나 필수 요구 누락은 계속 실패다.
5. 관측 결과를 근거로 최종 패키지를 만들고 출하 판단을 한다. 미실행 검사를 합격으로 표시하거나, static 평가 점수로 사실 정확성을 보증하지 않는다.

범용 사실 인증, 보안 인증, 강제 내부 독립 검토는 새 TTAK의 제품 약속에서 제외한다. 사용자가 사실 확인을 요청하거나 중요한 조건을 판단해야 할 때는 해당 주장에 맞는 출처·코드·계산을 사용한다. 검사 가능한 기능은 검사하며, 지침의 동의 여부를 사실 증거로 쓰지 않는다. 알려진 209 오류가 해결됐다는 주장은 새 행동 검증 전까지 하지 않는다.

이번 단계는 연구·선택·새 지침 설계·오프라인 평가까지다. 자동으로 192개 비교나 새 모델 실행을 시작하지 않았고, 기존 runtime을 교체하거나 출하하지 않았다.
