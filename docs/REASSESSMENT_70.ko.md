# 서브에이전트 독립 재평가 70

2026-09-10. **현재 계산 결과 → 자유 자연어 재작성 경로의 제품 통합과 추가 문구 진단을
보류한다. 남은 진단 2회와 전체 비교 516회를 보존한다. 출하 목표·모델·네 기능·비교 기준은 유지한다.**

사용자 요청으로 서브에이전트 3개를 병렬 사용했다. 판정 감사, 아키텍처 대안, 평가·예산을
독립적으로 검토했고, root는 로컬 원자료와 제품 진입점을 확인해 통합했다. 에이전트에는
검토된 일반 사례·요구조건만 전달했다. 에이전트의 의견은 증거의 대체물이나 추가 Haiku/Luna
품질 trial로 세지 않는다. 평가 전략에는 root 반론 후 한 차례 재검토가 있었다.

## 독립 검토의 결론과 채택 여부

| 검토 | 독립 의견 | root 통합 판단 |
|---|---|---|
| `verdict_audit` | 상대가 읽는 값을 쓰지 않는다는 주장은 실제 read/write 관계와 반대. 유효한 완화책과 추가 일반화 오류는 분리해야 함 | H2/Q1 실패 유지. 실제 원자료에서도 H3와 Q2는 이미 pass였음을 확인. 전 항목 실패로 확대하지 않음 |
| `architecture_review` | 계산 결과를 자유 문장으로 바꾸는 경계가 취약. 허용된 주장 ID와 고정 렌더러, 또는 출력 채널을 소유하는 runtime 검토 | 대안으로만 기록. 도구 출력만 구조화하면 기존 마지막 재작성 문제는 남으므로 즉시 채택하지 않음 |
| `evaluation_strategy` | 초기에는 남은 1회로 실패 계층 재확인을 제안 | 계층은 이미 실제 기록으로 확인됐다는 root 반론 후 권고 철회. 현재 2회를 보존하고 구조적으로 다른 개입이 생길 때만 사용 |

두 번째 설명에서 직렬 조정과 Serializable을 모두 유효한 완화책으로 언급하는 것만으로
오류는 아니다. 진단 66은 두 방식이 동일한 새 상태 읽기를 보장하는 것처럼 연결한 표현의
정밀도가 미해결인 기록이다. 모든 해석에서 명백한 오답으로 재분류하지 않는다.
반면 진단 69의 교차 읽기 부정은 자신의 예제와 직접 모순된다. 의도상 다른 말을 하려
했을 가능성은 있어도 사람이 문장을 고쳐서 통과로 세지는 않는다.

## 실제 목표와 현재 증거

현재 요구의 모델·추가 합격 기준은 [LOW_MODEL_RELEASE](LOW_MODEL_RELEASE.ko.md)에 기록돼 있다.
과거 Sonnet 조건은 새 Haiku 결과로 바꾸지 않는다.

| 요구 | 현재 근거 | 결론 |
|---|---|---|
| 두 호스트에서 네 기능·혼합 과제의 모든 필수 품질 | 개발 진단 60의 작은 과제는 기능 검사 통과. 설명 69는 Haiku 필수 실패. 전체 16과제 현재 후보 비교 미완료 | 미충족/미입증 |
| 원본 대비 중대 퇴보 없음 | 과거 일부 기록은 있지만 현재 후보의 완전한 동일 조건 비교가 없음 | 미입증 |
| 기본 모델 대비 같은 항목의 반복 개선, 호스트별 최소 한 기능 | 개발 60: Haiku 동률 2회, Luna 우세 방향이 반복마다 바뀜. 리뷰 61: baseline도 정답. 설명 68: 단일 통과 | 미입증 |
| 정확한 native 입력과 도구 계산 | 64·66·68·69에서 일부 성공 관측과 해시·재계산 증거 | 구성요소/진단 범위의 근거 |
| 한 번 설치한 제품에서 실제 동작 | 현재 제품은 정책·스킬·lifecycle hooks. 실험용 계산/검토 모듈은 제품 진입점에 연결되지 않음 | 최근 도구 진단을 제품 합격으로 계산할 수 없음 |

`hooks/hooks.json`에는 SessionStart, SubagentStart, UserPromptSubmit만 등록돼 있다.
`hooks/ttak.cjs`는 활성화 상태와 문맥 주입을 처리하며 최종 답변을 검사·교체하지 않는다.
제품 manifest·hook·정책·스킬 및 주요 관측 기록의 해시를
`.superpowers/reassessment-70/evidence.json`에 고정했다.

중단된 69의 미실행 두 행은 실패 때문에 생긴 결측이며 성공으로 채우거나 평균으로
추정하지 않는다. Luna 68의 통과는 보존하지만 성공 관측을 고른 뒤 반복 기준점으로
삼았다는 선택 편향도 유지한다. 두 번의 관측은 사용자 합의상의 반복 증거가 될 수 있어도
실패율·일반화·인과 효과의 통계적 보장은 아니다.

## 실패가 남은 위치

입력 시나리오 정확성 → 도구 계산/설명 정확성 → 최종 모델 문장 생성 중,
69에서 앞의 두 단계는 통과하고 마지막 단계가 실패했다. 이 위치를 다시 찾기 위한
동일 호출은 불필요하다. 실제 structured response와 독립 재계산 일치가 이미 남아 있다.

문단별 검토·수정, 근거 제공, 인용 주소, 원문 복사 요구, 실행 순서 설명 보강에는 각기
다른 국소적 효과가 있었지만 현재 조건의 최종 설명 품질을 안정적으로 해결하지 못했다.
그렇다고 모든 프롬프트/모델/도구 접근이 불가능하다고 증명한 것은 아니다. 현재 후보를
또 실행할 근거와 프로젝트 전체의 가능성은 구분한다.

## 호스트 문서로 재확인한 경계

아키텍처 에이전트가 제시한 주요 사실은 root도 공식 문서에서 다시 확인했다.
아래는 현재 문서의 기능이며, 로컬 고정 버전 2.1.266/0.153.4에서 새 hook을 실행해
검증했다는 뜻은 아니다. hook·전역 설정·프로필은 변경하지 않았다.

- Codex `Stop`의 block은 기존 최종 답변을 교체하는 대신 새로운 continuation prompt를
  만들어 모델을 계속 실행한다. 도구 hook도 완전한 강제 경계로 보지 말라고 명시한다.
  확인한 문서에서 양 호스트 공통의 최종 답변 교체 계약은 확보하지 못했다.
  [Codex hooks](https://learn.chatgpt.com/docs/hooks)
- Claude Code `MessageDisplay.displayContent`는 화면의 표시 텍스트를 바꾸지만 transcript와
  모델이 보는 내용은 바꾸지 못한다. 문서상 hook 실패 시 원문 표시로 돌아갈 수 있어
  화면 교체만으로 전체 전달 정확성을 보장할 수 없다. `Stop` 역시 재작성을 유도하는 기능이다.
  [Claude Code hooks](https://code.claude.com/docs/en/hooks#messagedisplay-output)

따라서 새 Stop hook이나 display hook을 붙이면 해결된다고 가정하지 않는다. 화면만 고친
결과를 실제 응답·재개 문맥까지 정확해진 것으로 보고하지 않는다.

## 대안의 실제 범위와 결정

| 대안 | 가능한 이점 | 해결하지 못하는 것/변경되는 것 | 지금 결정 |
|---|---|---|---|
| 기존 지침·도구 prose 추가 보강 | 작은 표현 차이를 유도할 수 있음 | 같은 자유 재작성 단계와 이미 반복된 오류 | 신규 진단 배정 안 함 |
| 또 다른 LLM 검토자/다수결 | 일부 오류 발견 | 검토자 오류, 누락, 비용 및 최종 재작성 오류 | 자동 정확성 인증 경로로 채택 안 함 |
| 허용된 claim ID 선택 + 결정적 렌더러 | 닫힌 주장 집합의 표시 정확성 | 모델이 마지막에 다시 쓰면 동일 문제. 주장 집합 밖의 범용 설명은 미해결 | 출력 채널·지원 범위를 먼저 설계해야 하는 후보 |
| verified artifact + 자유 해설 | 근거 확인에 도움 | 해설이 틀리면 원래 최종 설명 품질 실패를 상쇄하지 못함 | 도구 artifact만으로 출하 기준 충족 처리 금지 |
| 별도 출력 제어 runtime/UI | 최종 표시 경로를 소유할 가능성 | 설치·세션·인증·사용 흐름·지원 주제·유지 비용 재설계 | native plugin의 작은 수정으로 자동 채택하지 않음 |

아키텍처 보고의 “결정적 최종 렌더링”을 원래 사용자가 요구한 필수 조건으로 승격하지
않는다. 원래 목표는 고정 범위의 반복 품질이며 범용 무오류 보장은 아니다. 그러므로
최종 교체 hook의 부재가 원래 목표의 불가능성을 증명하지는 않는다. 다만 현재 접근의
실패가 확인된 상태에서 다른 경로를 채택하려면 그 효과와 제품 적합성을 입증해야 한다.

## 다음 작업의 순서와 중단 기준

1. 현재 자유 재작성 경로를 출시 후보에 통합하지 않고 진단 69를 종료 상태로 보존한다.
2. 새 모듈을 곧바로 만들기 전에 **최종 출력 경로 설계**를 작성한다. 모델이 정하는 값,
   검증기가 확인하는 값, 사용자에게 실제 표시되는 내용, transcript/재개 내용, 미지원
   주제·오류 처리, 두 호스트의 공통점/차이, 네 기능 및 16과제의 지원 여부를 명시해야 한다.
3. 이 설계가 기존 native 사용 흐름을 보존하지 못하면 별도 runtime이 필요한 이유와
   구체적인 사용자 경험·범위·운영 비용 변경을 제시한다. 현재 목표를 임의로 축소하거나
   unsupported/unknown 응답을 성공으로 세지 않는다.
4. 모델 호출 없는 검증으로 모순 출력, 근거 없는 대안 추가, unknown을 확정으로 바꾸는
   입력을 통과시키지 않는지 확인할 수 있는 구체적 구현이 생긴 뒤에만 남은 호출을 배정한다.
   고정 사실 card만 통과하고 최종 모델 문장은 그대로인 구현은 이 조건을 만족하지 않는다.
5. 적합한 변경이 없으면 2회를 모두 보존한다. 새 변경이 있어도 첫 실패는 즉시 중단한다.
   두 번 성공하더라도 전체 기준 달성을 주장하지 않으며 추가 증거·비용을 다시 산정한다.

이미 조정에 쓴 전문가 과제는 holdout이 아니다. 원래 고정 16과제는 수용 시험으로
유지하며 임의로 제거·교체하지 않는다. 일반화 주장을 위한 미노출 과제가 필요하면
별도 검증 계획으로 명시해야 한다. 그 호출을 기존 192 subject/516회에 몰래 추가하지 않는다.
추가 예산, 상위 모델, 기능 제외를 지금 해결책으로 요청하지 않는다. 해결할 구조가
구체화되기 전에 호출 수만 늘리는 것은 권하지 않는다.

## 산출물과 검증

이번 산출물은 독립 재평가 통합 보고와 로컬 근거 해시다. 제품 코드·스킬·후크·중단된
장부는 변경하지 않았다. 원자료의 H3/Q2 pass 유지, 16과제 수, 실제 등록 hook 종류,
결과·판정 연결을 확인했다. 문서 참조 경로와 diff 공백을 검사한다. 동작 변경이 없어
제품 회귀 테스트나 native 진단을 재실행하지 않았다.

추가 native CLI 호출 0회. 누적 **698회(Claude 413, Codex 285)**, 진단 잔여 **2회**,
전체 비교 **516회** 미사용이다. 서브에이전트 분석은 별도 분석 작업이며 low-model 품질
성공으로 계산하지 않는다. 전체 출하 목표는 미완료다.
