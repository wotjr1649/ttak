# 남은 3회 반복 진단 고정 계획 69

상태: 사용자 승인 후 첫 Haiku 실행에서 필수 오류를 확인해 배치를 중단했다.
누적 698회, 진단 잔여 2회, 전체 비교 배정 516회 미사용이다. 나머지 두 행은 미실행이다.

## 관측 결과

`01.haiku`, 세션 `2a4aadaf-a227-40ea-a9f7-586280b50bc0`를 1회 실행했다. 실제
모델·입력·thinking, 올바른 시나리오와 계산 결과 일치, 정상 종료 및 하위 프로세스 0개를
확인했다. 실행 시간은 약 20.8초다.

최종 답변은 Alice가 Bob을 읽고 Alice를 변경하며 Bob은 그 반대로 동작한다고 설명한 뒤,
어느 트랜잭션도 상대가 읽는 값을 쓰지 않는다고 했다. 제공된 계산 결과와 자신의 예제를
직접 부정하므로 H2와 Q1이 실패다. 추가로 lock-level serialization을 유일한 해결책으로
단정하고, 겹치는 상태를 읽는 어떤 두 트랜잭션도 병렬 실행할 수 없다고 일반화해
mitigation_scope와 claim_accuracy도 실패했다. 근거 인용은 실제 답변에 결합해 보존했다.

`operator-review.json`의 stop 판정을 장부에 반영했고, 재개 확인에서도
`status: stopped`, `used: 1`, `pending: 01.haiku`를 확인했다. `02.haiku`와
`03.luna`는 예약하거나 실행하지 않았다. 남은 두 호출은 이 배치를 재개하는 데 쓰지 않는다.

이 결과는 현재 계산·설명 전달 방식이 Haiku에서 필수 품질을 반복 충족한다는 가설을
지지하지 않는다. Luna 68의 단일 통과를 취소하지는 않지만 양 호스트 합격으로 일반화할
수 없다. 제품 통합·전체 비교는 진행하지 않았으며 범용 저모델 능력의 불가능성을 증명한
것도 아니다. 원본 계획·코드·프롬프트·결과·판정은 보존했고 기준을 낮추거나 답변을 고쳐
통과로 세지 않았다. 세부 계수는 Claude 413회, Codex 285회다.

아래는 고정한 원래 계획이다. 중단된 행을 다시 실행할 지시가 아니다.

`tests/release/cases.json`의 `explain-expert` 기준을 그대로 사용한다.

|---|---|

| H2 | 서로 다른 행을 쓰더라도 교차 행 불변식이 깨지는 이유 |
| H3 | 행 단위 원자성만으로 해결된다고 주장하지 않는 유효한 완화책 |

앞 다섯 항목이 원래 hard/quality 기준이다. 뒤 네 항목은 이미 진단 68에서 확인한
전달·충실성·정확성 조건을 명시적으로 기록한 것이다. 원문 복사는 요구하지 않는다.
어떤 항목도 모델의 자기 평가나 도구 응답 일치만으로 품질 통과로 바꾸지 않는다.

## 진행·중단 방식

각 `step` 명령은 최대 한 행만 실행하고 `awaiting_content_review`로 끝난다.
다음 행을 실행하려면 직전 결과의 모든 항목이 `pass`인 근거 있는 수동 검토가 필요하다.
검토는 사용자가 매번 승인하는 절차가 아니라 실행 담당 에이전트의 품질 검토다.

결과는 기존 `review-screen-ledger.cjs`가 배타적으로 예약하고 보존한다. 결과의 해시와
검토 판정을 연결하며, 검토의 인용문은 실제 답변에 있어야 한다. 아래 조건으로 진행한다.

- 실행·모델·입력·도구·응답 감사 실패: 이후 모든 행 중단, 재시도 없음.
- 필수 또는 품질 항목의 `fail`이나 `unknown`: 이후 모든 행 중단.
- 검토가 아직 없음: 다음 행을 실행할 수 없음.
- 이미 예약했으나 결과가 없음: 재실행 금지. 상태/프로세스를 조사하며 자동 재시작하지 않음.
- 코드·프롬프트·실행 파일·계획 해시 변경: 진행 거부. 배치 도중 수정해서 이어가지 않음.
- 동시에 같은 행을 실행하거나 순서를 건너뛰려는 시도: 거부.

`operator-review.json`에는 판정, 이유, 고정 순서의 9개 항목과 인용 근거,
`wrapper_review_pass`, receipt의 `result_sha256`을 기록한다. `review` 명령은 이를
검사한 뒤 append-only `decision.json`을 남긴다. 판정은 실행 승인 자체를 대신하지 않는다.

## 실행 범위와 비용

승인 대상은 기존 두 구독 프로필에서 동일한 로컬 `scenario_explain`을 세션 한정으로
연결해 위 순서대로 최대 3회 실행하는 것이다. 전역 설정·설치된 제품을 바꾸지 않는다.
기본 셸·웹 도구는 끄고 해당 계산 도구만 사용한다. API 키·추가 크레딧·상위 모델·fallback은
사용하지 않는다. 호스트 인증 정보는 MCP 계산기에 필요하지 않다.

각 행은 CLI 1회, 모델 실행 120초와 정리 10초, stdout 1 MiB/stderr 64 KiB로 제한한다.
서버 연결당 MCP 호출 상한은 3회이며 CLI 호출 수와 별도로 기록한다. Windows Job Object로
하위 프로세스를 정리한다. 버전 확인은 모델 호출이 아니다. 장부는 호출 예약을 보수적으로
1회 차감하며, 버전 확인 단계에서 실패한 경우 실제 모델 호출 여부는 attempt 기록과 구분한다.
세 모델 호출을 모두 수행하면 누적 700회, 진단 잔여 0회가 된다. 전체 비교용 516회는 사용하지 않는다.

준비 확인은 모델을 호출하지 않는다.

```powershell
Set-Location -LiteralPath 'D:\AI_DEV\ttak\.superpowers\worktrees\first-release'
& 'C:\Program Files\nodejs\node.exe' '.superpowers/scenario-repeat69.cjs' check 3d4864f36bfc74b29224013f7d897ba23320a329fd0cf73bbfba268bab14e6a8
```

실행 승인 후 담당 에이전트가 다음 형식으로 한 행씩 실행·검토한다. 이 문서 작성 시점에는 미실행이다.

```powershell
& 'C:\Program Files\nodejs\node.exe' '.superpowers/scenario-repeat69.cjs' step 01.haiku 3d4864f36bfc74b29224013f7d897ba23320a329fd0cf73bbfba268bab14e6a8
```

검토 기록을 작성한 뒤 같은 해시로 `review 01.haiku`를 수행한다. 통과한 경우에만
`02.haiku`, 다음 `03.luna`에 같은 절차를 적용한다. 전체를 무조건 연속 실행하는 루프는 없다.

## 검증과 해석 한계

관련 로컬 검사 16개가 통과했다. 미검토·부정 판정·변조 결과·중복 예약·중단된 실행의
재실행을 막는지, JSON 응답을 정확히 비교하는지, 틀린 근거 인용이나 일부 미확인 판정으로
다음 단계가 열리지 않는지 확인했다. 기존 Luna 68의 실제 기록을 새 공통 감사에 통과시켰고,
답변·세션·텍스트/구조화된 도구 응답 일치를 재확인했다. 새 모델 호출은 없었다.

모두 통과하면 수정본의 같은 전문가 과제에서 Haiku 2회, Luna는 기존 68을 포함해 2회
관측한 것이다. Luna 68은 성공 관측 후 기준 기록으로 선정했으므로 선택 편향을 공개한다.
조정에 사용하지 않은 과제, 네 기능 전체, 설치 제품, 기본/원본 대비 반복 개선은
입증되지 않는다. 결과를 전체 출하 비교의 성공 실적으로 자동 전환하지 않는다.
