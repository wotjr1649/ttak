# Luna 리뷰 기록 재사용 감사 — 61

2026-09-10. 모델 호출 없이 `review-already-small`의 과거 Luna 기록 6개를 대조했다.
기본·원본·TTAK 각각 두 반복이다. **이 기록의 관측 조건은 현재의 같은 리뷰를 분석하는
과거 근거로 참조할 수 있지만, 새로 실행한 시험이나 전체 출하 합격으로 자동 계산하지 않는다.**

## 확인한 것

- 네이티브 기록의 CLI `0.153.4`, `gpt-5.6-luna`, `high`, 기본 지침 해시와 provider가 일치한다.
- 기록된 승인·sandbox·permission profile·personality·collaboration 설정 등의 비교가 일치한다.
  불투명한 설정 해시의 일치는 기록하며, 그것만으로 모든 내부 동작이 같다고 해석하지 않는다.
- 각 네이티브 기록은 이전 입력 감사의 해시와 같고, 저장된 답변도 실제 assistant 출력과 같다.
- 과제와 rubric은 현재 파일과 같다. 실제 입력은 CRLF 9개를 포함하므로 현재 LF 리터럴과
  바이트가 같지는 않다. 줄바꿈을 정규화한 내용은 각 기록에서 정확히 한 번 일치한다.
- 현재 리뷰 스킬과 세 정책의 파일 해시가 당시와 같다. 변경된 설명 스킬은 frontmatter가
  같고, 과거·현재 설명 본문 모두 해당 리뷰 입력에 나타나지 않는다. 현재 리뷰 본문의 실제
  입력 횟수도 다시 계산해 TTAK 조건에서 1회임을 확인했다.
- 과거 수집기의 command·parse·activation·plugin 선택·preflight 함수는 현재와 AST가 같다.
  환경 구성의 공통 허용 목록도 같다. 수집기 변경의 추가 모델 고정과 검사는 Claude 경로다.

기본 모델과 원본, TTAK의 여섯 답변은 모두 이 작은 함수에 불필요한 복잡성 지적이 없다는
타당한 결론을 냈다. 기본 모델도 이미 필요한 판단을 제공했다. 설명량 차이만으로 TTAK의
반복적인 실질 개선을 인정하지 않는다.

## 적용 범위와 보존

이 감사는 한 리뷰 과제에 한정된다. 다른 과제, 변경된 설명 스킬이 로드된 과거 응답,
Sonnet 응답의 Haiku 대체에 확대하지 않는다. 최종 비교에 재사용하려면 새 비교 계획에
원본 실행 ID·입력/출력 해시와 대상 실행 조건을 명시적으로 연결해야 한다. 후보나 실제
수집·인코딩·활성화 조건이 바뀌면 재감사한다. 현재 `release_reuse_qualified`는 false이며
기존 기록의 합격 표시나 전체 비교 호출 배정을 바꾸지 않았다.

`.superpowers/reuse-audit-61/`에 관측과 판정을 보존했다. 최초 스크립트가 이 CLI에 없는
event 필드에서 답변을 찾은 문제는 실제 `assistant/output_text` 구조를 확인해 수정했다.
최초 스크립트·관측도 남겼고 원본 세션이나 답변을 고치지 않았다. 셸 구문 검사 차단은
검토 가능한 로컬 스크립트로 분리하는 정상 경로로 해결했다. 콘솔 문자 인코딩 오류도
기존 파일의 손상으로 판단하지 않았다.

추가 모델 호출은 0회다. 누적 693회, 진단 잔여 7회, 전체 비교 배정 516회는 유지한다.
