# 모델 실행 시간 예산 변경 — 2026-09-14

사용자 요청에 따라 모델 실행의 고정 120초 상한과 기본값을 제거했다.
시간 초과만으로 답변 품질 FAIL을 판정하지 않는다. 실행 예산 소진으로 답변을
확인하지 못했다면 실행 중단·품질 미검증으로 남기며, 합격으로도 계산하지 않는다.
과거 고정본·실패·시간 초과·미실행 기록은 변경하지 않는다.

## 실행 계약

- 호출자는 모델·추론 설정과 관측 지연을 고려한 유한 `timeoutMs`를 실행 전에
  명시한다. 다른 고정 기본값으로 대체하지 않았으며 생략하면 실행 전에 거부한다.
- `createNativeInvoker`는 `options.timeoutMs`, `budgetFor`는 두 번째 인수,
  `prepare`/`preparePacketRun`은 마지막 `timeoutMs` 인수를 사용한다.
- `createQualityPlan(cases, {claude, codex})`는 호스트별 밀리초 예산을 받고,
  각 행과 합계에 보존한다. 고정된 모델·추론 설정이 바뀌면 예산도 다시 산정한다.
- 직접 실행하는 기존 연결 probe와 native `--prepare`는 해당 프로세스의
  `TTAK_NATIVE_TIMEOUT_MS`를 요구한다. 전역 환경이나 프로필은 변경하지 않았다.
- Windows Job과 상위 watchdog은 명시된 실행 예산, 기존 정리 예산과 시작 여유를
  사용한다. 새 최대값은 타이머 표현 범위를 위한 것이며 사용 승인이나 추천값이 아니다.
  기존 실행 예약의 유효기간·전체 실행 기한도 계속 적용된다.
- 결과 제출 MCP의 별도 120초 타이머는 제거했다. 감독되는 native 실행의 수명과
  stdio 종료가 이를 관리한다. 입력 크기·메시지 수·프로토콜 검사는 유지한다.
- 기존 Codex 진단의 wait는 60초 단위로 조회하되 조회 시간 초과만으로 자식을
  닫지 않는다. 전체 실행 예산과 프로세스 트리 정리가 바깥에서 실행을 제한한다.

이는 모든 종류의 timeout을 없앤 변경이 아니다. 모델 추론 시간과 관리 명령,
로컬 테스트, 입출력·프로세스 정리 시간을 구분한다. 닫힌 배치 186과 그 이전
실행 스크립트는 역사적 고정본으로 보존하며 새 실행 계획으로 재사용하지 않는다.

## 출하 영향

이번 요청은 시간 제한 변경과 로컬 검증의 재개 범위다. 새 모델 실행·설치·활성화·
전체 비교는 수행하지 않는다. 제품 전체 개발이 자동으로 재개된 것은 아니다.

설명 사실 오류, 잘못된 승인, 실패 시 미검증 본문 출력, 반환 형식 불일치,
승인 범위 표현, 실제 취소·재개 검증과 수집기 갱신은 별도로 남아 있다.
수정된 동일 후보에서 정상·알려진 실패·새 사례·독립 반복을 확인하고,
Haiku/Luna의 네 기능·혼합 과제 192개 비교와 필수 품질·원본 대비 회귀·
기본 대비 반복 개선 기준을 통과해야 출하 가능하다. 516회 기존 요청 산정에는
최신 내부 검증 비용을 다시 반영해야 한다. 시간 제한 제거 자체는 품질 개선의 증거가 아니다.
