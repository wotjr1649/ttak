## 조건부 네이티브 검증안

새 후보의 진입 조건은 과거 실패에 개입하는 구체적인 변경, 정상/오류 대조 통과,
완성 답변 유지, 실제 설치 경로 검토, 정확한 버전·후보·수집기 freeze다.
80의 드라이버는 Haiku 실행만 관측됐다. Luna 드라이버는 준비 파일일 뿐이며
후보 설치·정상 hook 신뢰·ON 상태·MCP·정확한 skill 전달·완료 답변 감사까지 점검해야 한다.

권고하는 작은 게이트는 **8회**다. 아래는 기존 고정 과제의 제품 후보 조건만 검사한다.

| 순서 | 호스트 | 입력 |
|---|---|---|
| 1 | Haiku | 기존 전문가 과제 반복 1 |
| 2 | Luna | 기존 전문가 과제 반복 1 |
| 3 | Haiku | 개발·조정에 쓰지 않은 과제 1 |
| 4 | Luna | 같은 미사용 과제 1 |
| 5 | Haiku | 타당한 설명을 잘못 고치지 않는 정상 대조 |
| 6 | Luna | 같은 정상 대조 |
| 7 | Haiku | 기존 전문가 과제 반복 2, 새 세션 |
| 8 | Luna | 기존 전문가 과제 반복 2, 새 세션 |

이는 기존 과제만 호스트별 두 반복이고 정상·미사용 대조는 한 번씩인 작은 게이트다.
모든 종류를 두 번씩 확인하려면 12회가 필요하다. 8회로 실패율이나 범용 정확성을
통계적으로 입증한다고 주장하지 않는다. 첫 실질 실패면 뒤 행을 `UNRUN`으로 남긴다.
하네스 실패는 `HARNESS_ERROR`, 품질 실패는 `FAIL`로 구분하며 조용히 재실행하지 않는다.

현재 장부상 미사용 3회와 비교용 516회를 확인했다. **8회 게이트에는 5회가 추가로 필요하며
이는 승인된 상한이 아니라 제안이다.** 이번 사용자 요청은 계획·이관까지다.
다음 세션의 실제 요청이 이 계획과 호출 범위를 채택하는지 확인해야 하며, 계획 문서의
문구를 승인으로 간주하지 않는다. 3회만 가능한 경우 같은 freeze의 처음 3행만 실행하고
전체 게이트 미완료로 기록한다. 후보를 변경하면 이전 성공 행을 새 후보에 이어 붙이지 않는다.

게이트가 통과하면 원래 **192 subjects / 516회 계획**으로 넘어갈 준비가 된 것이지
출하 합격은 아니다. 16과제 × 2반복 × 3조건 × 2호스트, 모든 원래 H/Q 충족,
해당 원본 대비 미해결 중대 퇴보 없음, 각 호스트의 동일 항목에서 baseline 대비
두 반복 모두 실질 개선이라는 기준을 유지한다. 516은 subject/activation 388 + 채점 128이며
추가 제품 검토 모델을 도입할 경우 그 내부 호출·토큰 비용을 별도 계산해야 한다.
Opus/Sol 검증·게시·배포는 그 뒤의 별도 단계다.

## 모델과 역할

메인은 **`gpt-6-astra` / `max`**를 추천한다. 반복 실패의 인과관계, 공유 코드 영향,
판정 불일치와 비용·중단 판단에 추론을 집중하기 위한 작업상 선택이다.
이 선택이 후보의 합격이나 다음 세션 안의 출하 완료를 보장하지는 않는다.
[공식 Astra 문서](https://developers.openai.com/api/docs/models/gpt-6-astra)는 복잡한
종단 작업에 적합한 모델로 설명하며 max를 지원한다. 로컬 모델 목록에서도 지원을 확인했다.
로컬에 보이는 ultra를 선택할 필요는 없다. 역할과 모델을 명시해 배정하기 위해 max를 권고한다.

서브에이전트는 사용자 지정대로 **`gpt-5.6-luna` / `max` 고정**이다.
[공식 Luna 문서](https://developers.openai.com/api/docs/models/gpt-5.6-luna)와 로컬 목록에서
max 지원을 확인했다. 같은 Luna의 여러 독립 문맥은 독립 모델 계열이 아니다.

- 설계·회귀 감사: 과거 시도와 새 변경의 차이 및 정상 대조 검토.
- 호스트·수집기 감사: 설치 바이트, 전달, 최종 선택, 프로세스 정리, 장부 검토.
- 블라인드 품질 검토: 작성자와 분리한 새 문맥에서 고정 rubric으로 채점.

필요한 단계에서 두 블라인드 채점 문맥을 사용하되 작성한 후보를 스스로 최종 채점하지 않는다.
메인은 모든 Q1 통과 판정과 채점 불일치를 실제 문장·공식 근거로 재확인한다.
숨긴 모델명, 반복 순서, 판정 전 공개하지 않은 예상 답과 수정 이력을 기록한다.
검증 대상 Luna는 기존 **high**를 유지한다. 운영 서브에이전트의 max와 혼동해
대상 모델 조건을 바꾸지 않는다. Haiku는 기존 정확한 모델과 thinking 요청 조건을 유지한다.
